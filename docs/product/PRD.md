# CourseFlow 产品需求文档（PRD）

> 状态：已确认产品基线
> 版本：1.0
> 日期：2026-08-28
> 适用产品：macOS / Windows 本地优先桌面应用

## 1. 文档目的

本文定义 CourseFlow 首版要提供的产品行为。每项功能使用稳定编号，后续 User Flow、UI、架构、ADR、roadmap、backlog、测试和发布记录必须引用这些编号，不能仅以页面名称代替需求。

功能前缀含义：

- A：核心学习计划。
- A-ATTEND：不阻塞核心发布的可选课节出席记录。
- B：课程文件资料库。
- C-GRADE：成绩、等级与当前学期 GPA。
- C-TARGET：目标成绩条件扩展。

MVP 分层、完成定义、非目标和非功能要求见 MVP_SCOPE.md。已确认的核心任务流见 [CourseFlow MVP-A User Flow 设计](../superpowers/specs/2026-08-17-user-flow-design.md)。

## 2. 产品概述

### 2.1 目标用户

首版只服务管理自己当前学期课程的大学生，单人使用。教师、班级、共享课程和协作角色不在首版范围。

### 2.2 核心用户结果

用户能够：

1. 建立当前学期和课程，并为一门课程维护多个 LEC、TUT、PRA 上课时间。
2. 维护一次性或每周重复的课程任务，并正确处理 Reading Week 和单次例外。
3. 打开应用后立即知道今天、本周、下一个 Coursework 和下一个 Assessment。
4. 在受管理的本地资料库中按课程、分类和标签管理文件。
5. 手工维护评分项和成绩，查看单科等级、绩点及当前学期估算 GPA。
6. 在数据完整时估算达到课程或学期目标所需的后续平均成绩。
7. 在明确启用后手工记录课节出席，并按课程查看带覆盖范围的自报统计。

### 2.3 基本约束

- 无需登录，无远程业务后端，核心功能离线可用。
- 正式数据由用户手工输入或明确确认。
- 不包含 AI、OCR 或自动课程大纲抽取。
- 本地活动数据与云盘备份目录分开。
- 未知信息保持未知；估算结果不能冒充学校正式记录。
- 课节出席默认关闭；启用后也只表示用户自报，不代表学校正式考勤。

### 2.4 存储位置术语

- 活动数据目录：保存应用数据库、设置和文件索引，是正式结构化数据的唯一真相。
- 资料库根目录：保存课程文件，默认由 CourseFlow 在本地创建，用户可以更换，但不能位于云盘备份目录内。
- 云盘备份目录：用户选择的 iCloud Drive 或其他同步目录，只保存可恢复快照，不能作为活动数据目录或资料库根目录。
- 备份集：同一 Workspace 在一项持久备份配置下产生的一组快照；不同设备或重新建立的备份配置不得互相自动清理或合并。

## 3. 核心功能 A

### 3.1 学期

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-TERM-001 | 用户可以创建和编辑学期，填写名称、开始日期、结束日期及默认时区。 | 日期非法或结束早于开始时不能保存。 |
| A-TERM-002 | 同一时间设定一个当前学期，并可查看历史学期。 | 切换当前学期后，课程、任务和视图范围同步更新。 |
| A-TERM-003 | 当前日期超过学期结束日期后自动归档；归档不删除任何数据。 | 归档学期仍可查看；修正结束日期后可以恢复。 |
| A-TERM-004 | 用户可以在学期中设置一个或多个命名假期区间，包括 Reading Week。 | 假期支持编辑和删除，不写死具体学校日期。 |
| A-TERM-005 | 假期暂停周期课程及勾选“跟随教学周”的重复任务。 | 一次性作业、考试和明确截止事项仍正常显示。 |
| A-TERM-006 | 用户可以在设置中重置当前学期，一次性删除该学期及其课程、课节、任务与假期。 | 必须重新输入完全一致的学期名称才能执行；其他学期、本地备份与快照不受影响；删除后若已无任何学期则回到首次设置。 |

### 3.2 课程与课表

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-COURSE-001 | 用户可以创建、编辑和归档课程。课程包含代码、名称及可选的 section、教师、颜色和学分。 | 归档课程默认不进入当前视图，但历史数据保留。 |
| A-COURSE-002 | 一门课程可以配置多个不同的周期上课时间；创建课程时可以明确稍后再添加，或把零至多条课节与课程作为一个原子操作保存。 | 同一课程的 Lecture、Tutorial 和 Practical 可以同时存在；任一课节校验失败时课程与本批课节均不提交。 |
| A-COURSE-003 | MVP 的课节类型明确支持 LEC、TUT 和 PRA，并同时显示可理解的全称。 | 页面不能只依赖缩写或颜色区分类型。 |
| A-COURSE-004 | 每条周期课节规则包含一个确定星期、本地开始/结束时间、结束日偏移、地点及生效日期范围；新建或编辑时间使用五分钟粒度。 | 结束日偏移明确区分同日与次日，按 TermZone 解析后结束 Instant 必须晚于开始 Instant；修改开始时间不得自动顺延结束时间；只有地点未知时显示 TBA，星期和时间仍必填。 |
| A-COURSE-005 | 用户可以取消或修改单次课节，也可以修改该规则未来的所有课节。 | 修改单次实例不得破坏原周期规则或其他周实例。 |
| A-COURSE-006 | 系统对应用规则段和单次覆盖、排除已取消实例后的有效课节识别时间重叠，并以包含双方对象和时间的警告提示用户。 | 精确相接的时间边界不算重叠；警告不提交更改，用户明确继续后按原时间保存，系统不得擅自删除或移动课节。 |
| A-COURSE-007 | 课程具有位于学期范围内的教学开始日和结束日，默认继承学期范围；课节规则默认继承课程范围，并可使用位于课程范围内的更短范围。 | 晚开始或提前结束的 LEC/TUT/PRA 可以独立缩短范围，但不能越过课程或学期边界。 |

### 3.3 任务与重复事项

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-TASK-001 | 用户可以创建、编辑和删除与当前学期课程关联的任务。 | 任务始终能追溯到对应课程。 |
| A-TASK-002 | 用户明确选择任务组与类型。Coursework 包含 Homework、Assignment、Project、Research Paper；Assessment 包含 Quiz、Term Test、Midterm、Final；两个组都允许使用带自定义名称的 Other。 | 系统不根据标题、截止时间或成绩分类猜测任务类型；Midterm、Final 是明确的 Term Test 子类型，通用 Term Test 仍可单独选择。 |
| A-TASK-003 | 任务支持纯日期或精确截止时间；尚未确定时可保留为 TBA；精确时间使用五分钟粒度。 | TBA 任务不被放入虚构的日历时间；修改已有开始或截止时间不得静默改变其他时间字段。 |
| A-TASK-004 | 用户可以把任务设为每周重复，并配置开始日期、星期、截止时间和结束条件。 | 例如“每周六晚提交 CSC”能够按周出现。 |
| A-TASK-005 | 每个重复任务实例拥有独立状态。 | 完成本周任务不会自动完成后续周任务。 |
| A-TASK-006 | 编辑或删除重复任务时，可以选择“仅本次”或“本次及未来所有实例”。 | 已完成的历史实例不被未来修改静默覆盖。 |
| A-TASK-007 | 重复任务可以选择是否“跟随教学周”。 | 启用后 Reading Week 不显示该周实例；未启用时照常显示。 |
| A-TASK-008 | 任务支持待完成、已完成和已跳过状态，并可恢复。 | 删除、跳过和完成在界面及历史语义上明确区分。 |
| A-TASK-009 | 任意任务可以明确开启可选的 0–100% 自报进度；Project 与 Research Paper 在界面中优先展示该入口，其他类型从更多选项开启。 | 进度与任务分类独立且不参与成绩计算；完成状态显示为 100%，恢复待完成时还原完成前进度。 |
| A-TASK-010 | 每周重复任务的结束条件默认建议使用课程教学结束日，用户可以确认或缩短。 | 系统不得在用户未确认时静默创建超出课程范围的实例。 |

### 3.4 今日、本周与日历

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-VIEW-001 | “今天”视图按时间展示当日课节和任务。 | 当前课程、即将开始课程、已过期任务和已完成任务状态明确。 |
| A-VIEW-002 | “本周”视图展示本周课节、任务、截止事项及假期。 | Reading Week 中被暂停的周期实例不出现。 |
| A-VIEW-003 | 首页分别显示下一个 Coursework 和下一个 Assessment 及剩余时间。 | 两者只从对应任务组的合格实例中确定；Other 使用用户选择的所属组；没有候选时显示真实空状态，不显示模拟数据。 |
| A-VIEW-004 | 事项具有逾期、今天、即将到期、未来、已完成等明确状态。 | 状态不能只靠颜色表达；`pending`、未 `skipped` 且 deadline 已知的任务在 `today + 1 day` 或 `today + 7 days` 判为即将到期，在 `today + 8 days` 判为未来；TBA 保持 TBA、completed 保持已完成、skipped 保持已跳过，后三者均不属于即将到期。 |
| A-VIEW-005 | MVP 提供应用内提醒，包括今日列表、本周列表、倒计时和临近提示。 | 应用关闭时不承诺后台推送、邮件或系统通知。 |
| A-VIEW-006 | 首页显示今日已完成、今日待完成和按学期日历日期计算的学期进度。 | 计数同时覆盖任务与课节；出席功能关闭时课节按是否已结束统计，开启后按出席状态统计；假期和取消课节不计入。 |
| A-CALENDAR-001 | 日历统一显示周期课节、单次课节例外、一次性任务和重复任务实例。 | 课程与任务使用文字类型标记，不只依赖颜色。 |
| A-CALENDAR-002 | 日历至少提供周视图和按时间排序的议程视图。 | 无精确时间的事项进入待定区域，不强行落入时间格。 |
| A-CALENDAR-003 | 连续命名假期在周日历全天层显示为一个跨越起止日期的范围长条。 | 同一可见周不得把一个假期拆成每天一条；跨周时每个可见周最多显示一个连续片段。 |

#### 临近截止规则

`near-due` 的候选任务必须是 `pending`、未 `skipped` 且 deadline 已知；TBA 不进入该集合。`today` 是按 `TermZone` 取得的当前 `LocalDate`。date-only deadline 使用其 `LocalDate`；timed deadline 先按已存 zone context 投影到 `TermZone` 的 `LocalDate`。`near-due` 的闭区间为 `today + 1 day` 至 `today + 7 days`。当天由 Today/overdue 规则承载；`today + 8 days` 及更远不属于 `near-due`。该阈值不可配置，首发没有设置入口。

### 3.5 本地数据与备份

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-DATA-001 | 应用无需登录，所有正式数据默认保存在本机。 | 离线状态下核心 A 可完整使用。 |
| A-DATA-002 | 活动数据目录、资料库根目录与云盘备份目录具有明确边界；云盘备份目录必须与两个本地活动位置分开。 | 不能在云盘备份目录中运行活动数据库或受监控资料库。 |
| A-DATA-003 | 用户未设置云盘目录时仅保存本地副本。 | 未配置云盘不能产生持续错误或阻塞保存。 |
| A-DATA-004 | 配置云盘目录后，每次正式数据成功保存或资料库变化完成索引时触发异步备份；每次成功产生一份不可变、完整且可独立验证的快照，同一备份集保留最近两份已验证快照。 | 备份不阻塞本地保存；任一必需数据或资料库文件无法验证时整份快照失败且不发布。成功只表示快照已在所选目录本地发布并验证，不表示云盘服务已经上传；失败保留既有已验证快照、最后成功时间和待备份状态。 |
| A-DATA-005 | 用户可以从备份手动导入和恢复，并看到已验证、同步中或不完整、损坏、不兼容及未知条目的不同状态。恢复现有活动数据时，用户先预览影响和资料库目标，再明确确认一次完整替换。 | 只有重新验证通过的快照可进入影响预览；不能按目录时间自动选择“最新”副本，也不能静默覆盖或自动合并。确认后进入维护状态；容量不足必须在激活检查点前停止。当前 DATA 与已配置资料库健康时先创建完整的本地安全恢复集；无法完整保护时，只有原始证据可保持不变且用户确认独立警告才可受限恢复，否则停止。检查点前失败或取消不改变活动数据；检查点后中断只提供证据允许的继续或回滚，若两者都不安全则保持 recovery 并展示当前可证明状态。只有结构化数据重新打开、资料库全量对账并完成启动路由后才能显示成功，不得报告部分成功。 |
| A-DATA-006 | MVP 不提供多设备双向实时合并。 | 检测到不同副本时要求用户明确选择，不自动拼接。 |
| A-DATA-007 | 应用需要前向迁移正式结构化数据时，无条件先创建并验证最近一份本地迁移安全副本；用户始终可以查看和明确删除该副本。只有当前构建携带已发布的精确兼容 CourseFlow 版本时，副本才绑定该版本并提供显式回退。 | 无迁移的普通更新不创建副本；当前构建没有已发布的精确兼容版本时（开发构建，以及没有已发布前置版本的首个公开版本），副本仍然创建、验证、可查看和可删除，界面明确说明未绑定回退版本且不提供回退动作；不得因此跳过安全副本，也不得伪造或替代一个用户无法安装的版本。新副本完全验证后才能替换旧副本，始终最多保留一份且不按时间自动清理。迁移和回退中断时停止普通打开并按持久证据继续或取消；回退前明确说明迁移后结构化变化会丢失且不自动合并，真实资料库文件保持原位并在精确目标版本中全量对账。只有数据重新打开、资料库对账和启动路由完成后才显示成功。 |
| A-PLATFORM-001 | 首版支持 macOS 和 Windows 桌面环境。 | 两个平台均能完成核心 A 闭环。 |
| A-PLATFORM-002 | 公开版本只通过项目的 GitHub Releases 由用户在应用外手动取得和安装；应用不检查、下载或安装更新。 | 断网状态不产生更新错误或阻塞核心路径；产品中不存在更新 feed、自动下载、重启安装或静默更新入口。 |
| A-PLATFORM-003 | 程序安装与每用户本地数据使用稳定且独立的位置；安装、升级、回退和卸载不得把用户数据变成安装器拥有的文件。 | macOS 应用替换与 Windows per-machine 安装/卸载后仍定位同一用户数据；卸载保留活动数据、资料库、备份及迁移/恢复保护状态。 |
| A-PLATFORM-004 | 每个公开版本同时提供 macOS arm64、Windows x64 的完整已验证安装制品和机器可读发布清单，并冻结本版实际验证的 OS/build/参考设备。 | 任一平台未通过签名、安装、离线启动、核心旅程或数据保持验收时整个版本不发布；旧 OS、其他架构或单平台制品不被暗示为已支持。公开资产不得原地覆盖，问题通过新版本修复。 |

### 3.6 可选课节出席记录（MVP-A 外围目标）

本功能不得阻塞核心 A 的首次设置、课表、任务、日历、保存或发布验收。

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-ATTEND-001 | “设置 → 计划与日历”提供全局课节出席记录开关；默认关闭。 | 首次开启或跨日再次开启从学期时区当天 00:00 生效，包含当天较早已结束的课节但不改变更早日期；关闭在提交时刻立即生效且不删除已有记录；同一学期日期内关闭后再次开启只从再次开启的提交时刻生效。 |
| A-ATTEND-002 | 有效记录周期内、开始时刻早于关闭时刻的课节实例支持 Unmarked、Present、Absent、Late 和 Excused，并允许更正或恢复为 Unmarked。 | Unmarked 保持未知，不能自动按 Absent 处理；在关闭时刻或其后开始、位于关闭间隙、取消或假期抑制的课节不产生出席义务。 |
| A-ATTEND-003 | 用户可以从“今天”或课节详情手工记录 Present、Absent、Late、Excused，或恢复为 Unmarked。 | 记录是本地自报，不依赖定位、二维码、教师验证或网络；更正后各投影使用同一正式状态。 |
| A-ATTEND-004 | 每门课程显示 Present、Absent、Late、Excused、Unmarked、出席率和记录覆盖率。 | 出席率为 `(Present + Late) ÷ (Present + Late + Absent)`；Excused 不进入该分母；覆盖率分子包含四种已记录状态，分母只含有效记录周期内已结束且应上课的课节；任一适用分母为零时保持未知。 |
| A-ATTEND-005 | 开启出席记录后，首页今日摘要使用手工状态：Present 与 Late 计入完成但保持不同标签，已结束 Unmarked 进入待确认，Absent 单独显示，Excused 显示为已处理且不进入完成、缺席或待确认。 | 开启日以前和关闭间隙中开始的课节不会被回溯生成状态；关闭前已经具备资格或已有标记的课节继续保留；正在进行或未来且位于有效记录周期内的课节仍进入待完成。 |
| A-ATTEND-006 | 出席记录进入本地正式数据和可选备份，但功能故障不得阻止核心 A。 | 关闭开关或出席统计失败时，课程、课表、任务、日历和首页仍可打开和使用。 |

## 4. 课程文件资料库 B

|---|---|---|

### 5.2 成绩计算口径

- 单项百分比 = 已得分 ÷ 满分。
- 直接评分项的有效权重等于其课程权重。
- 等权分类组有 `N` 个项目且分类总权重为 `W` 时，每项有效权重为 `W ÷ N`；分类当前平均只对已出分项目取算术平均，未出分项目不按零处理。
- 已获得加权百分点 = 所有已出分且有效权重已知的单项百分比乘对应有效权重后求和。
- 已出分部分百分比 = 已获得加权百分点 ÷ 已出分且有效权重已知的总权重。
- 计算最终成绩要求所有顶层权重已知且合计 100%、分类非空、所有必需评分项已出分；否则只显示带覆盖范围的当前估算或未知原因。
- 未出分、满分缺失或权重未知的评分项不按零分处理。
- 当前学期估算 GPA 先把每门纳入课程的百分比映射为离散 grade point，再按课程学分加权；不能先平均百分数再换算 GPA。
- UTM 当前规则中 F 以 0.0 计入 GPA。CR/NCR、重修、SAC、EXT 等边界不在首版范围。
- 公开规则不足以完全复刻学校系统的 GPA 舍入过程，因此产品结果必须标记为估算。

## 8. 验收与可追溯性

- 每项功能的测试、User Flow、UI 页面说明、架构接口和 backlog 条目都应引用相应功能编号。
- 核心 A 的验收不得依赖 B、C1 或 C2 已完成。
