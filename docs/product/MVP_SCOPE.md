# CourseFlow MVP 范围与非目标

> 状态：已确认产品基线
> 版本：0.2
> 日期：2026-08-17

## 1. 范围原则

CourseFlow 采用分层首发。核心 A 用于验证“学生能否可靠地知道今天和本周要做什么”；可选出席记录作为 A 的外围目标独立验收；B、C1 和 C2 增加产品价值，但不能把考勤、文件系统或成绩预测风险带入核心发布路径。

本文定义范围门槛，不定义开发时间、人员安排或迭代日期；这些内容属于后续 roadmap 和 backlog。

## 2. 范围分层

| 范围编号 | 层级 | 包含功能 | 发布规则 |
|---|---|---|---|
| MVP-A | 核心 MVP | A-TERM-*、A-COURSE-*、A-TASK-*、A-VIEW-*、A-CALENDAR-*、A-DATA-*、A-PLATFORM-* | 必须完整通过 macOS 与 Windows 验收，能够独立发布。 |
| MVP-A-P | 外围 MVP | A-ATTEND-* 可选课节出席记录 | 只能在不改变核心 A 完成定义的前提下加入；可以与首发一起交付或随后更新，不得阻塞 MVP-A。 |
| MVP-B | 次级 MVP | B-FILE-* 课程文件资料库 | 只能在 MVP-A 稳定后进入发布验收，不得破坏核心计划闭环。 |
| MVP-C1 | 次级 MVP | C-GRADE-* 成绩、等级与当前学期估算 GPA | 只能在 MVP-A 稳定后进入发布验收；所有结果必须标记为估算。 |
| EXT-C2 | 条件扩展 | C-TARGET-* 目标成绩与所需分数 | 在 A、C1 的数据和计算规则稳定后加入；不得成为核心 MVP 发布阻塞项。 |

MVP-A-P、B 与 C1 都属于已经批准的首版产品范围，可以在同一次首发中交付。若它们威胁 A 的正确性或显著推迟核心验证，则允许随后以首版更新交付。

## 3. 难度评估

### 3.1 B：课程文件资料库

相对难度为中等。主要成本来自 macOS/Windows 文件权限差异、目录监听、索引与真实文件的一致性、同名冲突、预览和备份体积。以下边界使其可以作为次级 MVP：

- 只管理一个资料库根目录。
- 分类来自目录位置和用户标签，不分析文件内容。
- 允许任意文件，但只内置预览 PDF、常见图片和纯文本。
- 不做多人共享、在线编辑、版本历史和多目录聚合。

### 3.2 C1：成绩与 GPA

相对难度为中等。它是本地确定性计算，但需要严格区分未出分、零分、未知权重、当前估算和最终成绩。版本化 UTM 模板、课程学分加权和明确覆盖范围可以控制误解风险。

### 3.3 C2：目标计算

相对难度为中高。首版只计算剩余评分项所需平均分和未完成课程所需学分加权平均绩点，不自动把目标分配到每门课或每项任务。复杂条件评分留给后续独立规则引擎。

### 3.4 MVP-A-P：可选课节出席记录

相对难度为中等。它复用正式课节实例，但新增可切换的有效记录周期、未标记/已出席/缺席三态、历史不回溯约束、按课程统计和首页摘要联动。以下边界使其保持外围能力：

- 默认关闭，开启只从学期时区当天开始；更早课节不改变。
- 关闭不删除已有记录，再次开启也不补写关闭期间的课节。
- 打卡完全手工、自报和本地化，不做定位、二维码、教师验证或自动出席推断。
- 未标记保持未知，不按缺席处理；统计同时显示出席率和记录覆盖率。
- 模块不可用时，课表、任务、日历、首页和本地保存仍需完整工作。

## 4. 核心 MVP 完成定义

- MVP-DOD-001：新用户可在约 20 分钟内建立学期、课程、多条 LEC/TUT/PRA 课节及主要任务。
- MVP-DOD-002：今天、本周、下一个小任务和下一个大任务均来自同一组正式本地数据。
- MVP-DOD-003：Reading Week 正确暂停周期课节和跟随教学周的任务，同时保留一次性截止事项。
- MVP-DOD-004：重复任务支持仅本次删除/修改，以及本次和未来全部修改。
- MVP-DOD-005：关闭并重新打开应用后数据完整，离线状态下核心功能可用。
- MVP-DOD-006：本地保存失败、云盘备份失败和备份导入失败均不会静默损坏正式数据。
- MVP-DOD-007：macOS 与 Windows 均通过同一套核心行为验收。
- MVP-DOD-008：不存在要求用户登录、连接云端服务或配置 AI 才能完成的核心路径。

### 4.1 外围出席目标完成定义

- MVP-A-P-DOD-001：开关默认关闭；启用当天以前的课节及既有首页历史状态不改变。
- MVP-A-P-DOD-002：启用期内可以手工标记出席、缺席或恢复未标记，关闭后记录保留。
- MVP-A-P-DOD-003：课程统计同时显示已出席、缺席、未标记、出席率和记录覆盖率，分母不足时保持未知。
- MVP-A-P-DOD-004：出席保存或统计失败不阻塞任何 MVP-A 核心路径。

## 5. 明确非目标

- NG-001：账户系统、远程后端和服务端云同步。
- NG-002：多设备双向实时合并和冲突自动解决。
- NG-003：教师、班级、共享课程、协作编辑及权限角色。
- NG-004：AI、OCR、课程大纲自动抽取或自动修改正式数据。
- NG-005：浏览器、移动端、原生手机应用及网页版本。
- NG-006：邮件、短信、浏览器推送和系统级后台通知。
- NG-007：LMS、邮箱、Google Calendar、Apple Calendar 等外部平台自动同步。
- NG-008：子任务、任务依赖、关键路径及完整项目目标管理。
- NG-009：同时监控多个分散文件目录。
- NG-010：文件内容自动语义分类、在线编辑、多人共享和版本历史。
- NG-011：最低分剔除、最高 N 次、动态权重或条件评分方案等复杂课程评分规则。
- NG-012：正式成绩单复刻、AGPA、CGPA、历史 GPA、重修/SAC、CR/NCR 及项目录取规则。
- NG-013：自动把学期 GPA 目标拆分成每门课程、每项任务的指定目标。
- NG-014：保证估算结果与 ACORN 或学校正式记录完全一致。
- NG-015：ATTEMPT.md 中旧实现、旧页面或旧架构自动成为新版本要求。
- NG-016：教师或学校正式考勤、定位围栏、二维码签到、后台自动识别出席及考勤证明。
- NG-017：在 MVP 中实现本周负荷或番茄钟，或提前显示不可用的空入口。

## 6. 跨功能质量要求

| 要求编号 | 要求 |
|---|---|
| NFR-001 | 应用默认离线可用，未经用户明确操作不得上传课程、成绩或文件内容。 |
| NFR-002 | 正式数据写入采用可恢复方式；任何失败不得留下“界面显示成功、磁盘没有保存”的状态。 |
| NFR-003 | 活动数据目录、资料库根目录与云盘备份目录边界明确；备份位置与两个本地活动位置物理分离，备份带格式版本和完整性校验。 |
| NFR-004 | 日期、时间、重复规则和假期均按学期时区解释，并正确处理跨日与夏令时边界。 |
| NFR-005 | 未知日期、权重、成绩和文件状态保持未知，不使用零值或模拟数据补齐。 |
| NFR-006 | 关键状态使用文字说明，所有核心操作可通过键盘完成，不能只依赖颜色或 hover。 |
| NFR-007 | 删除学期、课程、重复规则或资料前明确展示影响范围，并优先提供可恢复操作。 |
| NFR-008 | 当前成绩、目标成绩及 GPA 始终展示计算范围、数据覆盖情况和“估算”标识。 |
| NFR-009 | 课程、任务、日历和首页不得分别实现互相矛盾的重复与 Reading Week 规则。 |
| NFR-010 | 文件系统发生权限丢失、外部移动或云盘不可用时，应用仍能打开并解释受影响资源。 |
| NFR-011 | 出席记录的启用/关闭必须保持历史稳定；未标记不能按缺席处理，关闭外围功能不得改变核心课表事实。 |

## 7. 范围变更规则

1. 新需求必须说明所属范围层级和对应功能编号。
2. 任何进入 MVP-A 的新增能力都必须证明它是完成核心用户结果所必需。
3. A-P、B、C1 或 C2 的实现不得要求核心 A 连接网络、登录账户或依赖出席/文件/成绩模块。
4. 后续复杂功能不得通过空入口、隐藏配置或未启用代码提前进入首版。
5. 若需求与本文件冲突，应先修改并重新确认产品文档，再进入架构或 backlog。
