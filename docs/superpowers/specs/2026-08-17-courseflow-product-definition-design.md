# CourseFlow 产品定义设计

> 状态：已由用户逐段确认
> 日期：2026-08-17
> 方法：Superpowers brainstorming

## 1. 设计目标

基于 ATTEMPT.md 中第一次尝试留下的证据，重新确立 CourseFlow 的立项说明、编号化 PRD、MVP 范围与非目标。旧实现只作为可行性和风险证据，不作为当前产品规范。

## 2. 已选择方案

采用“分层首发”：

- A 是能够独立验收和发布的核心 MVP。
- B 与 C1 是已批准的次级 MVP。
- C2 是不阻塞核心发布的条件扩展。
- 复杂评分、任务项目管理、协作和 AI 进入后续版本。

没有采用“A-only 首发后再决定其他模块”，因为受限后的文件资料库和基础成绩计算能够提供明显价值；也没有采用 A+B+C1+C2 全部作为同一发布门槛，因为文件监听和目标预测会显著扩大核心风险。

## 3. 已确认的关键决策

1. 首版面向管理自己当前学期课程的大学生，单人使用。
2. 产品是 macOS / Windows 跨平台桌面应用。
3. 无账户、无远程业务后端，核心功能离线运行。
4. 正式课程事实严格手工录入；AI 是未来可选能力。
5. 本地数据是唯一真相；独立云盘目录只保存自动备份，恢复通过手动导入。
6. 一门课程支持多条 LEC、TUT、PRA 周期课节。
7. 重复任务按独立实例工作，支持仅本次和本次及未来修改。
8. Reading Week 暂停周期课节和选择“跟随教学周”的重复任务，但不隐藏一次性截止事项。
9. MVP 提供应用内今日/本周/倒计时提醒，不提供后台推送。
10. 任务由用户明确选择 Coursework 或 Assessment，再选择对应类型；任务进度是独立能力，子任务、依赖和项目目标管理后续加入。
11. 文件资料库只监控一个用户指定根目录，并按目录确定性派生课程与分类标签。
12. 默认成绩模板基于 UTM Undergraduate 2026–2027，允许复制后编辑。
13. 首版 GPA 只显示当前学期估算 SGPA；学校正式记录、AGPA、CGPA 和复杂边界不在范围。
14. C2 只计算剩余评分项所需平均分和未完成课程所需加权平均绩点。

## 4. 产品级数据流约束

- 学期、课程、周期规则、任务和例外写入本地正式数据。
- 今日、本周、日历和倒计时都是同一正式数据的派生视图，不维护第二套事项。
- 本地正式数据保存成功或资料库变化完成索引后，才允许异步生成完整、不可变快照；只有所选目录本地发布并验证后才显示备份成功，同一备份集保留最近两份已验证快照。失败不能回滚或损坏本地成功写入，也不能发布部分快照。
- 文件资料库以真实文件为基础建立索引；应用上传和用户手动放入都进入同一索引流程。
- 成绩和目标结果由用户输入、版本化等级模板和确定性公式派生，并携带覆盖范围与估算状态。

这些是后续架构必须满足的产品约束，不是本轮的技术架构选型。

## 5. 错误与边界策略

- 保存失败保留用户输入，并明确正式数据是否改变。
- 云盘、目录权限或文件索引失败不阻止应用打开和使用不受影响的本地功能。
- TBA、未知权重、未出分、零分和数据不足分别建模并分别展示。
- 删除或修改周期事项前明确范围：仅本次、本次及未来或整个规则。
- 目标不可达时显示不可达，不输出负分或超过 100% 的伪结果。

## 6. 验收策略

- 每项后续测试引用稳定功能编号。
- A 的验收不依赖 B、C1 或 C2。
- 重复规则测试覆盖正常周、Reading Week、单次例外、未来修改和历史实例保留。
- 本地数据测试覆盖重启、保存失败、云盘失败、损坏备份和显式恢复。
- 文件测试覆盖应用上传、外部放入、移动、同名冲突、权限变化和重建索引。
- 成绩测试覆盖等级边界、F、零分、未出分、未知权重、覆盖不足、目标不可达和 UTM 模板。
