# CourseFlow 需求基线

本文把当前已确认 UI 与产品说明整理成可继续补充的需求基线。它回答“产品要做什么”；视觉构图、组件状态与交互细节仍以已确认 UI 为准，领域语义分别由 `CONTEXT.md`、数据模型和 interface 文档约束。

## 1. 裁决规则

1. 当前 UI 已确认的六个一级入口是：**总览、课程、日历、任务、资料、统计**。实现可拆分子 route，但不能改变用户看到的信息架构。
2. 需求描述与当前 UI 有重大冲突时，以 UI 为准，冲突内容不进入产品 backlog、数据模型或验收标准。
3. UI 中的具体课程、日期、百分比、统计数值都是 fixture，不是默认业务数据；生产页面只消费真实 view model。
4. 正确性、安全、隐私、正式数据审核边界和 WCAG 2.2 AA 属于硬约束。因这些约束必须偏离 UI 时，按设计基线流程记录 deviation，不静默重设计。
5. 本文只记录本轮能够从 UI 与描述共同确认的行为。未定义的评分换算、标签治理、Reading Week 例外等放入开放问题，不提前猜规则。

## 2. 产品目标与范围

CourseFlow 帮助学生把学期、上课安排、课程事项、资料证据与成绩放进一套可核对的个人学习计划。首个完整产品范围包括：

- 建立学期和课程，并维护每门课程的一组周期性上课安排。
- 在总览看到学期进度、今日课程、下一节课、教室和近期行动。
- 在日历同时查看上课实例与有确定日期的课程事项。
- 以短期推进和中长期准备组织任务，并用标签筛选或识别任务。
- 查看成绩组成与占比；出分后由用户手工录入结果，计算当前已获成绩。
- 上传课程资料并手工对照原文录入；只有 DeepSeek AI 去留门禁通过时，才增加“抽取候选 → 用户审核 → 正式记录”路径。
- DeepSeek 当前为条件性能力；门禁通过后才在个人中心配置用户自己的 API Key 并启用抽取/规划，失败或最终未验证则以纯手工产品发布。
- 仅用正式数据生成统计洞察；数据不足时显示真实空状态。

## 3. 六个一级页面

| 一级页面          | 核心问题                 | 已确认职责                                                                        | 不属于该页的职责              |
| ----------------- | ------------------------ | --------------------------------------------------------------------------------- | ----------------------------- |
| 总览 `/dashboard` | 今天先做什么？           | 学期进度、今日课程、下一节倒计时/地点、近期任务、负荷、重要评估、待审核与风险摘要 | 编辑完整课表或编造统计数字    |
| 课程 `/courses`   | 每门课当前怎样？         | 当前学期课程列表、课程摘要、下一事项、成绩组成入口、添加/编辑课程及课节           | 跨课程日历编排                |
| 日历 `/calendar`  | 何时上课或截止？         | 周视图/列表、周期课节实例、确定日期事项、TBA 区、筛选与 ICS 导出                  | 把未知日期强行落格            |
| 任务 `/tasks`     | 先做什么、持续准备什么？ | 今天/明天、本周短期任务、中长期大任务、筛选、搜索、标签、完成状态和进度           | 把课节当作可勾选任务          |
| 资料 `/sources`   | 原始资料在哪里？         | 按课程/项目组织、上传、预览、打开手工表单；`AI_ENABLED` 时增加导入/审核/Evidence   | 上传或审核前直接修改正式计划 |
| 统计 `/insights`  | 学习节奏与负荷怎样？     | 已定义的负荷、完成、课程分布等 Insight 及其口径/质量；未定义时为空状态            | 用 fixture 或缺失数据推断成绩 |

`/terms`、`/courses/new`、`/courses/[courseId]/grading`、`/imports/[runId]`、`/settings` 与右上角头像触发的个人中心 overlay 等是上述一级页面服务的支持 surface，不新增一级导航。

## 4. 功能需求与验收

### 4.1 学期与学期进度

- 用户可创建、编辑、归档和切换学期。
- 学期至少填写名称、起止日期和 IANA 时区；创建课程时必须先确定所属学期。
- 学期校历周次从 `start_date` 所在、按用户 `week_starts_on` 对齐的周记为第 1 周；Reading Week 不增加教学周编号，例外后的教学周编号顺延。若学校使用不同编号，后续通过显式 term policy 配置，不由 UI 猜测。
- 总览的学期进度按当前日期在学期本地日期范围内计算，并明确处于“尚未开始 / 进行中 / 已结束”的哪一状态。`term-progress-v1` 用学期内、排除 `suppresses_meetings=true` 校历例外后的日期计算已过比例；Reading Week 内显示例外名称且进度暂停。百分比不等于课程完成度。
- Reading Week 是学期日历中的命名停课区间，不计为正常教学周；它默认暂停周期课节实例，但不会取消已有课程事项、考试或用户单独添加的日历事件。
- 学期表单为未来校历例外保留可扩展入口；首版至少支持 Reading Week，不能把日期写死在应用代码中。

验收：Reading Week 内默认不生成 Lecture/Tutorial/Practical 实例；区间前后仍按同一周期规则生成；显式例外可以覆盖默认停课行为。

### 4.2 课程与添加课程

添加课程是分步、可回退的流程，至少覆盖：

1. 选择/创建学期，并确认课程时区。
2. 填写课程代码、名称、可选 section、教师与课程色键。
3. 添加零到多条课节：类型、可选 section、星期、开始/结束本地时间、地点、有效日期范围。
4. 核对 Reading Week 与其他停课例外，预览将生成的每周安排和时间冲突。
5. 保存；课程可以先无课节保存，之后补充。

同一门课程可有多个不同时间的课节。首版课节类型至少包括 `Lecture`、`Tutorial (TUT)`、`Practical (PRA)`；UI 显示全称并可附常见缩写，不能只用难以识别的缩写。地点允许为空或 TBA，并保留原始文本；首版把线上地点当名称展示，不自动打开不可信链接。相同时间、同课程重复课节和跨课程重叠应在保存前给出明确 warning；除结构非法外不武断阻断用户。Office Hour 等一次性安排作为时间区间课程事项加入日历；只有确实周期重复时才建 `other` 课节。

### 4.3 今日课程、下一节课与日历

- 总览列出“今天”在用户显示时区下的正式课节实例，至少显示课程代码、开始/结束时间和地点。
- 下一节课从尚未结束的今日/近期正式课节实例中计算；开始前显示剩余时间，进行中显示“正在上课”和剩余时长，今天没有后续课程时显示明确空状态。
- 倒计时由 server 提供目标 instant 与生成时间，客户端只做显示层计时；刷新或跨 DST 后必须由 server truth 校正。
- 日历同时显示课节实例和有确定日期的课程事项，两者有文字类型标识，不能只靠颜色区分。
- Reading Week 或显式取消的实例不出现在今日课程和普通日历投影；TBA 课节/事项留在待定区域。

### 4.4 任务、分组与标签

- “任务”是课程事项的行动视图，不新建第二套与 `Course Item` 竞争的正式实体。
- 分组沿用当前 UI：今天/明天优先、本周推进（短期小任务）、持续准备（中长期大任务）；`near/major/tba` 是派生视图分类，不持久化为互斥业务类型。
- 短期默认采用当前 UI 的未来 7 天窗口；中长期包括重要评估、里程碑或超出短期窗口但需要持续准备的事项。确切阈值可在版本化 policy 中调整。
- 用户可给课程事项添加零到多个标签，并按标签筛选。标签是用户拥有、学期内可复用的规范对象；显示名大小写保留，trim + 大小写折叠后不得重复。
- 首版提供由事项类型/状态生成的系统标签展示（如作业、实验、复习、日期待定），并允许用户创建自定义标签；系统标签不可被重命名成自定义业务含义。
- 完成、取消、删除遵守课程事项的既有状态语义；完成任务不会删除其历史负荷和成绩关联。
- 课程事项可选保存 `0–100%` 的用户自报进度，以支持当前 UI 的长期准备进度；它不是成绩百分比。完成状态在展示上等价于 100%，但历史自报值不参与成绩计算。

### 4.5 成绩组成与成绩录入

- 每门课程可查看一个或多个评分方案、成绩组成、占比与复杂规则说明；未知占比保持未知，合计不等于 100% 仅 warning。
- 当前成绩按选中的一个评分方案计算，默认使用 primary；多个替代方案不会合并成一份成绩。
- 某个成绩组成公布结果后，用户手工录入 `earned` 与 `possible`，系统据此得到该组成百分比。缺少任一值时结果保持未知，不用 0 补齐。
- 当前已获成绩只基于**已出分且权重已知**的组成计算，并同时显示：已获得加权百分点、已出分部分百分比、已覆盖总评权重。不得把未出分组成按 0 分计入。
- 首版支持用户提供的字母等级表，等级集合限 `A/B/C/D/F` 五个分类；每档保存明确的百分比下界。边界必须单调且无重叠；“当前字母等级”由已出分部分百分比派生，并始终与覆盖权重同屏，不允许百分比和等级形成两套冲突真相。
- 学分值属于课程，可由用户填写非负且至多三位小数的数值；页面显示该课程学分。学分不是单项成绩，首版不自动宣称 GPA 或“已获得学分”，也不推断学校的及格/绩点规则。
- Gradebook/成绩单文件如进入自动抽取，仍遵守 Candidate → Review Decision → 正式数据；MVP 的成绩结果先走用户手工录入。
- 首版一项成绩组成录入一个汇总结果；`Weekly quizzes` 等组合项由用户录入老师当前公布的汇总 earned/possible。逐次小测明细与 `best N of M` 自动结算需先确认规则后扩展。

示例口径：一项权重 20%、得分 80%，贡献 `1600 bps`（总评 16 个百分点）。若当前只有该项出分，则显示“已获 16/100；已出分部分 80%；覆盖总评 20%”，而不是把课程当前成绩显示为 16%。

### 4.6 资料与统计

- 无论 AI 决策如何，资料页都支持私有上传、安全校验、原文件预览和从旁打开既有手工表单；正式课程事实不能因上传自动变化。
- 只有产品模式为 `AI_ENABLED` 时才显示解析、Candidate、Evidence 和审核工作台，并继续遵守“候选不是正式数据”；课节、Reading Week、任务标签、评分方案等若未来从资料抽取，也必须逐字段保留 Evidence 并经审核。
- 统计页保持现有入口与视觉构图。只有定义了输入范围、公式、最小数据量和数据质量的 Insight 才能显示真实数值。
- 成绩相关统计不因加入手工成绩而自动进入统计页；需要单独定义产品用途和口径。

### 4.7 数据在哪里填写

| 数据                                                      | 主要填写位置                                | 原因                                           |
| --------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------- |
| 学期名称、起止日期、默认时区、Reading Week                | `/terms` 的创建/编辑流程                    | 它们影响整个学期的课节展开、进度和日期解释     |
| 周起始日、显示时区、可复用 A/B/C/D/F 等级表               | `/settings`                                 | 属于用户偏好或跨课程规则；课程中只选择/覆盖    |
| 显示名称与头像                                            | 个人中心的“账户与隐私”                     | 属于账户资料，不与普通显示偏好或 AI 凭据混排   |
| 课程代码、名称、section、教师、颜色、学分、等级表选择     | `/courses/new` 或课程编辑                   | 属于课程身份与展示                             |
| Lecture/TUT/PRA、星期、起止时间、地点、有效区间、单次例外 | 添加/编辑课程的“上课安排”步骤               | 同一课程可一次核对多条课节及 Reading Week 影响 |
| 课程事项、时间、负荷、标签                                | `/tasks`、课程 timeline 或统一事项表单      | 三个入口调用同一 command，不产生重复记录       |
| 评分方案、组成、占比、出分结果                            | `/courses/[courseId]/grading`               | 让权重、结果和覆盖口径在同一课程上下文核对     |
| 原始 PDF/图片与手工录入入口                               | `/sources`、课程资料页                       | 保持私有原文可回看，不因上传自动改计划         |
| Candidate/Evidence（仅 `AI_ENABLED`）                     | `/imports/[runId]`                           | 保持导入状态与审核决定可追溯                   |
| DeepSeek API Key 与 AI 状态（仅 `AI_ENABLED`）            | 个人中心的“AI 配置”                         | 凭据是账户级秘密，不属于课程或普通设置字段     |

### 4.8 条件性个人 AI 配置与规划助手

AI 当前处于 `AI_PENDING`，不是已承诺功能。最终评审只有两种结果：全部硬门禁通过后进入 `AI_ENABLED`；任一门禁失败或仍未验证则进入 `MANUAL_ONLY`，删除所有 AI 界面、密钥入口、解析/候选功能、服务端 adapter 和 AI 专用数据结构，不接入其他模型顶替。详细判据与清理清单见 [AI 去留门禁](../architecture/AI_ASSISTANT.md#3-deepseek-ai-去留门禁)。

以下行为只适用于 `AI_ENABLED`。个人中心中的凭据输入框是**用户自带的 DeepSeek API Key 配置框**；AI 的提问框必须在视觉和无障碍语义上与密钥框分开，不能用一个含糊输入同时承担凭据与对话。

- 右上角头像打开个人中心 overlay。`ui-v1` 只冻结了头像按钮，没有冻结该 overlay、AI 面板或动效；`AI_GO` 前只可保留隔离设计稿，不能把 AI surface 纳入生产基线。通过后才补齐设计、动画、键盘/focus 与错误状态，登记并由用户确认新基线版本。普通实现不得改写 `ui-v1`。
- P3 只允许用户配置 `DeepSeek` 凭据，目标模型默认是服务端 allowlist 中的 `deepseek-v4-pro`。不向用户开放任意 `baseURL`、代理地址或模型字符串。
- 未配置凭据时，所有 AI 操作保持禁用，并在操作附近持续显示“AI 功能暂不可用，请先配置 DeepSeek API Key”；不能只弹 toast，也不能让资料或任务进入永远排队的状态。手工课程计划与资料上传仍可使用。
- 密钥只经 HTTPS 提交给 CourseFlow 服务端。保存时服务端验证凭据能认证且账户可见目标模型；这不代表余额、限额或后续请求一定成功。页面只回读 `unconfigured/available/invalid` 等状态、掩码提示和验证时间，永不回读明文。
- 凭据可用时，个人中心可显示 server 提供的当前 AI 提供商、目标模型 alias 和最后验证时间；这些是只读展示元数据，不能由客户端配置或伪造。未配置/无效时不猜测提供商。
- 个人助手首版可做：解释今日/本周优先级；基于正式 `ScheduleSnapshot` 生成日/周计划草稿；把一个正式课程事项拆成步骤与工作量草稿；解释确定性计算出的冲突、负荷和当前成绩覆盖口径；根据自然语言生成现有事项表单的预填建议。
- AI 规划草稿不是正式数据。选择草稿只预填现有手工表单，用户仍需核对并提交；服务器继续执行所有权、日期、成绩、版本和领域校验。模型没有写工具，不能自动完成/修改/删除事项、录入成绩或接受导入 Candidate。
- DeepSeek API 当前只接收文本。PDF、图片和截图必须先经过 CourseFlow 的受限解析/OCR，得到带页码/文本块定位的输入；不得把原始对象 URL、图片或 PDF 当作模型已理解的输入。
- `AI_ENABLED` 首版默认关闭联网搜索，不发送未审核 Candidate、原始文档、其他课程外数据或不必要的历史。成绩预测、“需要考多少分”、GPA 和最终成绩仍不在范围内，不能通过 AI 绕过既有产品边界。
- 开发、普通 CI、E2E 和截图不用真实 key；最终受控评测由用户临时提供 key，完成后立即撤销。没有 key、未完成评测或条款未确认都属于 `UNVERIFIED`，最终评审时按失败处理。
- `MANUAL_ONLY` 下个人中心不出现 AI，`/sources` 只提供上传/预览与“打开手工表单”；不运行 OCR 抽取、不生成 Candidate/Evidence。用户手工录入后，时间线、负荷、冲突、成绩汇总与 ICS 仍照常由确定性规则派生。

验收：首先形成明确的 `AI_GO` 或 `MANUAL_ONLY` 报告，不允许“尚未验证但先上线”。仅在 `AI_GO` 后，才要求无密钥状态可从头像入口理解并恢复；密钥不会出现在 DOM 回读、日志或错误响应；受控真实 DeepSeek 调用能从页级文本产生 Candidate 并走完审核；个人助手只读取当前用户的有界正式快照，草稿未经现有表单确认不会改变任何正式记录。`MANUAL_ONLY` 则以 AI 入口、route、表和供应商依赖全部清理，以及手工资料录入闭环通过为验收。

## 5. 跨页面一致性

- 今日课程、课程摘要和日历中的课节来自同一 `ScheduleSnapshot`，Reading Week/取消/时区语义一致。
- 任务页、总览近期任务、课程下一事项和负荷视图读取同一正式课程事项；标签只影响组织和筛选，不改变事项日期或权重。
- 课程页、任务长周期卡片和成绩页显示同一成绩组成及占比；结果录入后由同一 Gradebook 投影计算。
- 所有倒计时、相对日期和学期进度都显示其时区/基准日期，不由各 React 组件独立判断。

## 6. UX 检查结论

按 `ux-heuristics` 与 `typeui-fundamentals` 联合静态检查，已冻结 P1/P2 范围没有 severity 3/4。AI 方案当前评分 **8/10**，最高为 severity 2：真实能力/条款未验证、助手/供应商错误尚未冻结、`AI_PENDING` 若直接显示会形成死入口。通过“`AI_GO` 前不进入生产基线”和 `MANUAL_ONLY` 等价路径消除了流程级严重风险；只有门禁通过后，才需补齐验证中、可用、无效、余额不足、限流/供应商失败、生成中/取消、引用/假设和草稿预填，完成浏览器验收后才能升至 10/10。

TypeUI 审核要求：密码与提问框均使用持久 label；每个 panel 只有一个明确主动作；输入与相邻按钮等高且不换行；状态不只依赖颜色/toast；44px 目标、可见 focus、Escape 关闭并返回头像、reduced-motion 均为硬要求。`1280x900` 是像素基线；200% zoom 不要求截图逐像素一致，但为了满足本文 WCAG 2.2 AA，关键表单/overlay 仍不得丢内容、控件或键盘操作。

强制交互约束：

- 添加课程和成绩录入均保留取消/返回与字段级错误，提交失败不丢输入。
- `Lecture/TUT/PRA`、课节/事项、短期/中长期、成绩百分比/覆盖权重必须有文字解释，不能要求用户猜色彩或缩写。
- 倒计时、保存、导入和审核必须展示系统状态；关键成功/错误不能只用 toast。
- 任何 hover 揭示的信息都有键盘、触摸与静态文本等价入口。
- 添加课程/成绩表单的输入在默认态可辨识，标签不由 placeholder 代替；相邻操作同高且不折行；正常横屏桌面下保持主操作可见。
