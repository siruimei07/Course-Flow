# CourseFlow 产品需求文档（PRD）

> 状态：已确认产品基线
> 版本：0.1
> 日期：2026-08-17
> 适用产品：macOS / Windows 本地优先桌面应用

## 1. 文档目的

本文定义 CourseFlow 首版要提供的产品行为。每项功能使用稳定编号，后续 User Flow、UI、架构、ADR、roadmap、backlog、测试和发布记录必须引用这些编号，不能仅以页面名称代替需求。

功能前缀含义：

- A：核心学习计划。
- B：课程文件资料库。
- C-GRADE：成绩、等级与当前学期 GPA。
- C-TARGET：目标成绩条件扩展。

MVP 分层、完成定义、非目标和非功能要求见 MVP_SCOPE.md。

## 2. 产品概述

### 2.1 目标用户

首版只服务管理自己当前学期课程的大学生，单人使用。教师、班级、共享课程和协作角色不在首版范围。

### 2.2 核心用户结果

用户能够：

1. 建立当前学期和课程，并为一门课程维护多个 LEC、TUT、PRA 上课时间。
2. 维护一次性或每周重复的课程任务，并正确处理 Reading Week 和单次例外。
3. 打开应用后立即知道今天、本周、下一个小任务和下一个大任务。
4. 在受管理的本地资料库中按课程、分类和标签管理文件。
5. 手工维护评分项和成绩，查看单科等级、绩点及当前学期估算 GPA。
6. 在数据完整时估算达到课程或学期目标所需的后续平均成绩。

### 2.3 基本约束

- 无需登录，无远程业务后端，核心功能离线可用。
- 正式数据由用户手工输入或明确确认。
- 不包含 AI、OCR 或自动课程大纲抽取。
- 本地活动数据与云盘备份目录分开。
- 未知信息保持未知；估算结果不能冒充学校正式记录。

### 2.4 存储位置术语

- 活动数据目录：保存应用数据库、设置和文件索引，是正式结构化数据的唯一真相。
- 资料库根目录：保存课程文件，默认由 CourseFlow 在本地创建，用户可以更换，但不能位于云盘备份目录内。
- 云盘备份目录：用户选择的 iCloud Drive 或其他同步目录，只保存可恢复快照，不能作为活动数据目录或资料库根目录。

## 3. 核心功能 A

### 3.1 学期

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-TERM-001 | 用户可以创建和编辑学期，填写名称、开始日期、结束日期及默认时区。 | 日期非法或结束早于开始时不能保存。 |
| A-TERM-002 | 同一时间设定一个当前学期，并可查看历史学期。 | 切换当前学期后，课程、任务和视图范围同步更新。 |
| A-TERM-003 | 当前日期超过学期结束日期后自动归档；归档不删除任何数据。 | 归档学期仍可查看；修正结束日期后可以恢复。 |
| A-TERM-004 | 用户可以在学期中设置一个或多个命名假期区间，包括 Reading Week。 | 假期支持编辑和删除，不写死具体学校日期。 |
| A-TERM-005 | 假期暂停周期课程及勾选“跟随教学周”的重复任务。 | 一次性作业、考试和明确截止事项仍正常显示。 |

### 3.2 课程与课表

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-COURSE-001 | 用户可以创建、编辑和归档课程。课程包含代码、名称及可选的 section、教师、颜色和学分。 | 归档课程默认不进入当前视图，但历史数据保留。 |
| A-COURSE-002 | 一门课程可以配置多个不同的周期上课时间。 | 同一课程的 Lecture、Tutorial 和 Practical 可以同时存在。 |
| A-COURSE-003 | MVP 的课节类型明确支持 LEC、TUT 和 PRA，并同时显示可理解的全称。 | 页面不能只依赖缩写或颜色区分类型。 |
| A-COURSE-004 | 每条课节规则包含星期、本地开始/结束时间、地点及生效日期范围。 | 地点未知时显示 TBA；结束时间必须晚于开始时间。 |
| A-COURSE-005 | 用户可以取消或修改单次课节，也可以修改该规则未来的所有课节。 | 修改单次实例不得破坏原周期规则或其他周实例。 |
| A-COURSE-006 | 系统识别时间重叠并提示用户。 | 冲突只产生警告，不擅自删除或移动课程。 |

### 3.3 任务与重复事项

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-TASK-001 | 用户可以创建、编辑和删除与当前学期课程关联的任务。 | 任务始终能追溯到对应课程。 |
| A-TASK-002 | 用户明确选择任务规模为“小任务”或“大任务”。 | 系统不根据标题或截止时间擅自改变规模。 |
| A-TASK-003 | 任务支持纯日期或精确截止时间；尚未确定时可保留为 TBA。 | TBA 任务不被放入虚构的日历时间。 |
| A-TASK-004 | 用户可以把任务设为每周重复，并配置开始日期、星期、截止时间和结束条件。 | 例如“每周六晚提交 CSC”能够按周出现。 |
| A-TASK-005 | 每个重复任务实例拥有独立状态。 | 完成本周任务不会自动完成后续周任务。 |
| A-TASK-006 | 编辑或删除重复任务时，可以选择“仅本次”或“本次及未来所有实例”。 | 已完成的历史实例不被未来修改静默覆盖。 |
| A-TASK-007 | 重复任务可以选择是否“跟随教学周”。 | 启用后 Reading Week 不显示该周实例；未启用时照常显示。 |
| A-TASK-008 | 任务支持待完成、已完成和已跳过状态，并可恢复。 | 删除、跳过和完成在界面及历史语义上明确区分。 |
| A-TASK-009 | 大任务可以记录可选的 0–100% 自报进度。 | 进度不参与成绩计算；完成状态显示为 100%。 |

### 3.4 今日、本周与日历

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-VIEW-001 | “今天”视图按时间展示当日课节和任务。 | 当前课程、即将开始课程、已过期任务和已完成任务状态明确。 |
| A-VIEW-002 | “本周”视图展示本周课节、任务、截止事项及假期。 | Reading Week 中被暂停的周期实例不出现。 |
| A-VIEW-003 | 首页分别显示下一个小任务和下一个大任务及剩余时间。 | 没有对应任务时显示真实空状态，不显示模拟数据。 |
| A-VIEW-004 | 事项具有逾期、今天、即将到期、未来、已完成等明确状态。 | 状态不能只靠颜色表达。 |
| A-VIEW-005 | MVP 提供应用内提醒，包括今日列表、本周列表、倒计时和临近提示。 | 应用关闭时不承诺后台推送、邮件或系统通知。 |
| A-CALENDAR-001 | 日历统一显示周期课节、单次课节例外、一次性任务和重复任务实例。 | 课程与任务使用文字类型标记，不只依赖颜色。 |
| A-CALENDAR-002 | 日历至少提供周视图和按时间排序的议程视图。 | 无精确时间的事项进入待定区域，不强行落入时间格。 |

### 3.5 本地数据与备份

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| A-DATA-001 | 应用无需登录，所有正式数据默认保存在本机。 | 离线状态下核心 A 可完整使用。 |
| A-DATA-002 | 活动数据目录、资料库根目录与云盘备份目录具有明确边界；云盘备份目录必须与两个本地活动位置分开。 | 不能在云盘备份目录中运行活动数据库或受监控资料库。 |
| A-DATA-003 | 用户未设置云盘目录时仅保存本地副本。 | 未配置云盘不能产生持续错误或阻塞保存。 |
| A-DATA-004 | 配置云盘目录后，每次正式数据成功保存或资料库变化完成索引时触发异步备份，生成或更新带版本和完整性信息的快照。 | 备份不阻塞本地保存；失败时保留上一个有效快照并显示最后成功时间和错误状态。 |
| A-DATA-005 | 用户可以从备份手动导入和恢复。 | 导入前验证备份格式与完整性，不能静默覆盖现有数据。 |
| A-DATA-006 | MVP 不提供多设备双向实时合并。 | 检测到不同副本时要求用户明确选择，不自动拼接。 |
| A-PLATFORM-001 | 首版支持 macOS 和 Windows 桌面环境。 | 两个平台均能完成核心 A 闭环。 |

## 4. 课程文件资料库 B

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| B-FILE-001 | CourseFlow 默认创建并管理一个本地资料库根目录，用户可以更换该目录。 | 更换前显示影响，验证新目录可读写，并确认它不在云盘备份目录内。 |
| B-FILE-002 | 系统根据已有学期和课程创建对应文件夹。 | 新建或重命名课程后，文件夹映射保持一致且不丢失文件。 |
| B-FILE-003 | 课程文件夹提供“考试、笔记、作业、练习、其他”等建议分类，用户可以增删或重命名分类。 | 分类变化不会静默删除已有文件。 |
| B-FILE-004 | 用户可以通过应用上传文件，系统将文件复制到选定课程和分类目录。 | 原始文件被移动或删除后，资料库中的副本仍可使用。 |
| B-FILE-005 | 用户也可以通过系统文件管理器手动把文件放入受管理目录。 | 应用运行时自动发现；关闭期间的变化在下次启动或重新扫描时发现。 |
| B-FILE-006 | 文件根据所在目录自动获得学期、课程和分类标签。 | 在受管理目录内移动文件后，派生标签同步更新。 |
| B-FILE-007 | 用户可以为文件添加额外的自定义标签。 | 自定义标签与目录派生标签分开保存，目录变化不删除自定义标签。 |
| B-FILE-008 | 资料管理器支持按课程、分类、标签和文件名查找资源。 | 组合筛选结果只来自真实文件索引。 |
| B-FILE-009 | 用户可以在应用中重命名、移动、打开和删除文件。 | 文件操作失败时索引不得显示虚假成功状态。 |
| B-FILE-010 | 允许保存任意文件类型；PDF、PNG、JPEG、WebP 和纯文本提供应用内预览，其他格式使用系统默认应用打开。 | 不支持预览的文件仍可定位和打开。 |
| B-FILE-011 | 同名文件不得被静默覆盖。 | 用户必须选择保留两份、替换或取消。 |
| B-FILE-012 | 云盘备份包含资料库文件及其课程、分类和标签元数据。 | 恢复后文件与标签映射一致。 |
| B-FILE-013 | MVP 只监控一个资料库根目录。 | 分散在其他目录中的文件不会被承诺自动发现。 |

## 5. 成绩、等级与当前学期 GPA C1

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| C-GRADE-001 | 每门课程可以建立一个直接权重评分方案，包含考试、作业等评分项。 | 评分项支持名称、权重及可选关联任务。 |
| C-GRADE-002 | 权重未知时保持未知；权重合计不等于 100% 时提示但不擅自修正。 | 未知权重不按零处理。 |
| C-GRADE-003 | 用户可以为评分项手工录入已得分与满分，或直接录入百分比结果。 | 未出分项与零分明确区分。 |
| C-GRADE-004 | 单科页面同时显示已获得加权百分点、已出分部分百分比及已覆盖总权重。 | 未出分项不按零分计入当前成绩。 |
| C-GRADE-005 | 用户可以建立和编辑 A+、A、A−、B+、B、B−、C+、C、C−、D+、D、D−、F 的分数线与绩点。 | 边界必须连续、单调且无重叠。 |
| C-GRADE-006 | 内置版本化的 UTM Undergraduate 2026–2027 模板，并允许复制后编辑。 | 模板记录来源、适用年份和核对日期，不静默覆盖用户副本。 |
| C-GRADE-007 | UTM 模板使用 A+/A=4.0、A−=3.7 至 F=0.0 的官方映射。 | 默认分数线与 UTM 官方规则一致。 |
| C-GRADE-008 | 用户可以为课程录入学分/课程权重，并选择使用计算结果或手工最终成绩。 | 手工最终成绩覆盖当前估算时必须明确显示来源。 |
| C-GRADE-009 | 单科显示百分比、字母等级、绩点及数据覆盖情况。 | 当前结果与正式最终结果使用不同状态标签。 |
| C-GRADE-010 | 当前学期估算 GPA 按“各课程绩点乘学分之和 ÷ 纳入课程学分之和”计算。 | F 以 0.0 纳入；缺少学分或成绩的课程列入未覆盖清单。 |
| C-GRADE-011 | 首版只显示当前学期的估算 SGPA，不把它称为 AGPA、CGPA 或正式 GPA。 | 页面明确说明 ACORN/学校记录才是正式结果。 |
| C-GRADE-012 | 计算过程不把临界百分比分数自动向上取整。 | 84.5 等估算值不得被自动提升为 85。 |
| C-GRADE-013 | 当前学期成绩总览列出每门课程的百分比、字母等级、绩点、学分、结果来源和数据覆盖情况。 | 总览与单科页面使用同一结果；不虚构“学期总百分比”。 |
| C-GRADE-014 | 每门课程明确选择一个等级与绩点模板；当前学期可以设置默认模板。 | 更换默认模板不静默改写已完成课程绑定的历史模板。 |

### 5.1 UTM 默认模板

模板名称：University of Toronto Mississauga — Undergraduate — 2026–2027。

| 最终百分制成绩 | Letter grade | Grade point |
|---:|:---:|---:|
| 90–100 | A+ | 4.0 |
| 85–89 | A | 4.0 |
| 80–84 | A− | 3.7 |
| 77–79 | B+ | 3.3 |
| 73–76 | B | 3.0 |
| 70–72 | B− | 2.7 |
| 67–69 | C+ | 2.3 |
| 63–66 | C | 2.0 |
| 60–62 | C− | 1.7 |
| 57–59 | D+ | 1.3 |
| 53–56 | D | 1.0 |
| 50–52 | D− | 0.7 |
| 0–49 | F | 0.0 |

官方依据：[UTM 2026–2027 Academic Calendar — Grades and Academic Record](https://utm.calendar.utoronto.ca/grades-and-academic-record)。完整核对记录见 [UTM 本科成绩等级与 GPA 规则](../research/utm-grading-gpa-rules.md)。

产品必须保留模板版本、来源地址和核对日期。用户编辑默认规则时创建个人副本，不能改变已存在学期使用的历史模板。

### 5.2 成绩计算口径

- 单项百分比 = 已得分 ÷ 满分。
- 已获得加权百分点 = 所有已出分且权重已知的单项百分比乘对应权重后求和。
- 已出分部分百分比 = 已获得加权百分点 ÷ 已出分且权重已知的总权重。
- 未出分、满分缺失或权重未知的评分项不按零分处理。
- 当前学期估算 GPA 先把每门纳入课程的百分比映射为离散 grade point，再按课程学分加权；不能先平均百分数再换算 GPA。
- UTM 当前规则中 F 以 0.0 计入 GPA。CR/NCR、重修、SAC、EXT 等边界不在首版范围。
- 公开规则不足以完全复刻学校系统的 GPA 舍入过程，因此产品结果必须标记为估算。

## 6. 目标成绩与所需分数 C2

| 功能编号 | 功能要求 | 核心验收 |
|---|---|---|
| C-TARGET-001 | 用户可以为课程设置目标百分比、字母等级或绩点。 | 字母等级和绩点目标转换为所选模板中的最低百分比要求。 |
| C-TARGET-002 | 系统计算剩余全部已知权重评分项需要达到的平均百分比。 | 已完成成绩、剩余权重和目标公式可解释。 |
| C-TARGET-003 | 用户可以为部分未完成评分项填写预期分数。 | 系统据此重新计算其他剩余项所需平均分。 |
| C-TARGET-004 | 只有一个剩余评分项时，系统显示该项需要达到的具体分数。 | 结果同时显示该项权重和可达性。 |
| C-TARGET-005 | 用户可以设置当前学期目标 GPA。 | 系统只计算未完成课程所需的学分加权平均绩点，不自动分配到每门课。 |
| C-TARGET-006 | 目标不可达到、已经达到或数据不足时显示明确状态。 | 不输出负分、超过 100% 或伪精确结果。 |
| C-TARGET-007 | 目标计算始终标记为估算。 | 缺少权重、学分或有效等级表时停止计算并解释原因。 |

复杂评分规则不属于 C2。后续评分规则引擎可以处理“11 次取最高 10 次”、按阶段成绩高低动态分配权重等场景，但首版不预留需要用户理解的空界面。

## 7. 共同产品状态

| 状态编号 | 产品行为 |
|---|---|
| STATE-001 | 空状态必须解释缺少什么以及用户可执行的下一步，不使用 fixture 或模拟数字。 |
| STATE-002 | 保存、文件操作、备份和导入失败时保留用户输入，并说明正式数据是否已改变。 |
| STATE-003 | TBA、未知权重、未出分和零分是不同状态，不能共用同一个空值文案。 |
| STATE-004 | 删除单次实例、未来实例、整个周期规则和正式记录是不同操作，必须显示影响范围。 |
| STATE-005 | 当前估算、用户手工最终成绩和学校正式记录是不同来源，必须在成绩界面明确区分。 |

## 8. 验收与可追溯性

- 每项功能的测试、User Flow、UI 页面说明、架构接口和 backlog 条目都应引用相应功能编号。
- 核心 A 的验收不得依赖 B、C1 或 C2 已完成。
- 重复事项至少覆盖：正常周、Reading Week、仅本次删除、仅本次修改、本次及未来修改、已完成历史实例保留。
- 成绩至少覆盖：零分、未出分、未知权重、合计不等于 100%、等级边界、目标不可达和数据不足。
- 数据至少覆盖：无云盘目录、云盘不可写、备份损坏、导入冲突和应用重启。
- 文件至少覆盖：应用上传、应用关闭期间手动放入、外部移动、同名文件、权限丢失和索引恢复。
