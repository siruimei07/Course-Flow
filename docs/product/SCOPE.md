# CourseFlow 产品范围

本文件定义版本范围与页面职责；细化后的行为和开放问题见 [需求基线](./REQUIREMENTS.md)。当前已确认 UI 的六个一级入口优先于早期 route 假设。

## 1. 产品定义

CourseFlow 是面向学生的课程要求整理工具。它把 syllabus、作业说明和截图中的分散信息整理成可核对的正式计划，并用“接下来要做什么、哪一周最忙、哪里发生冲突”回答日常规划问题。

它不是学校教务系统，也不替用户判断老师原意。遇到含糊日期、替代评分方案或互相矛盾的资料时，产品要把不确定性暴露出来，让用户选择。

## 2. 主要用户与核心任务

首版只有一种主要角色：管理自己课程的学生。

学生需要完成的核心任务：

1. 建立当前学期和课程。
2. 为课程维护 Lecture、Tutorial（TUT）、Practical（PRA）等周期课节和 Reading Week 例外。
3. 从总览查看今日课程、下一节倒计时、地点、学期进度和近期行动。
4. 上传一份课程资料并对照原文手工录入；仅当 DeepSeek 门禁通过时，才查看解析进度并审核抽取候选。
5. 修正或补充课程事项、任务标签、成绩组成、手工成绩结果和负荷估计。
6. 从任务、日历与跨课程雷达查看短期推进、中长期准备、繁忙周和冲突。
7. 导出当前学期或单门课程的 `.ics` 文件。
8. 若 DeepSeek 门禁通过，在个人中心配置自己的 API Key，并让 AI 基于已确认课程计划提供解释和草稿；否则保持纯手工流程。

## 3. MVP 范围

### 必须完成

- 学期与课程的创建、编辑、归档和切换。
- 一门课程维护零到多个周期课节，首版明确支持 Lecture、Tutorial（TUT）、Practical（PRA）、本地时间、地点与生效日期范围。
- Reading Week 作为学期校历例外；周期课节实例默认停开，并允许明确的单次取消、改期或保留。
- 总览显示学期进度、今日课程、下一节课剩余时间和地点；日历同时显示课节实例和课程事项。
- PDF、PNG、JPEG、WebP 课程资料上传；一组有序图片可视为一份资料。
- 私有 Source 文件存储、安全校验、原文预览，以及从预览旁打开现有手工表单。
- 手工新增和修改正式课程事项、评分方案、成绩组成、负荷估计。
- 课程事项的用户自定义标签，以及当前 UI 所示的短期/中长期行动分组与筛选。
- 成绩组成出分后的手工结果录入；显示已获得加权百分点、已出分部分百分比和已覆盖权重，未出分不按零分处理。
- 课程学分字段与用户确认的 A/B/C/D/F 百分比等级表；首版只做展示/换算，不计算 GPA 或宣称已获得学分。
- 单课程时间线与跨课程近期雷达。
- 每周负荷热力图，明确区分资料明确值、用户估计和启发式估计；周内明细列出具体事项落点。
- 确定时间区间重叠与截止日期扎堆的站内提醒。
- 单课程或学期 `.ics` 下载，事件 UID 稳定。
- 统计页真实路由、导航入口、空状态和稳定 query interface；不展示虚构指标。
- 产品只面向正常横屏桌面浏览器；当前冻结与新设计统一以 `1280x900` 为像素参考 viewport，不建立竖屏、窄屏或移动端产品布局。键盘路径仍须可用，重要状态不只靠颜色表达；日历、热力图等本质二维内容可在自身容器内滚动。200% zoom 不作视觉像素基线，但关键任务仍须满足 WCAG 2.2 AA 的内容与操作保留要求。

### 通过 `AI_GO` 后才纳入

- 异步 AI 导入状态和可恢复失败提示。
- 课程元数据、课程事项、考试/测验、日期、成绩组成与占比 Candidate。
- 字段级 Evidence：至少有 1-based 页码和短原文；能获得时增加标准化图片坐标。
- 接受、修改后接受、拒绝、标记重复的审核流程；接受时可明确新建正式记录或更新匹配的已有记录。
- 右上角头像触发的个人中心 overlay 增加 DeepSeek API Key 的配置、替换与撤销；无密钥时明确显示 AI 暂不可用。
- `deepseek-v4-pro` 的真实文本 API 接入：本地解析/OCR 后的资料抽取，以及基于有界正式快照的规划问答、日/周计划草稿、事项拆解和风险/成绩口径解释。
- AI 生成的变更只预填现有手工表单；用户明确提交后才调用既有 command，模型没有正式数据写权限。

当前模式为 `AI_PENDING`。最终评审任一硬门禁失败或仍未验证时进入 `MANUAL_ONLY`：上述条件性能力全部从发布范围删除，且不使用其他模型替代；通用上传/预览、手工表单与确定性投影继续属于 MVP。

### 明确延后

- 学校 LMS 自动同步、邮件自动读取。
- 多人协作、课程共享和教师账号。
- “需要考多少分”、最终成绩预测、GPA 与学分获得判定。
- 邮件、短信、push 等定时通知；MVP 的提醒位于应用内和导出日历中。
- 移动端/窄屏专用布局、原生移动应用和离线优先同步。
- OCR/AI 供应商管理后台、运行时插件市场。
- DOCX/PPTX 等额外格式；增加格式时走同一 Source Document seam。
- 自动代替用户接受“高置信度”候选。
- 从 syllabus/LMS 自动抽取或同步周期课节、Reading Week、成绩单结果；首版先手工维护，后续仍走 Candidate 审核。
- AI 直接接收 PDF/图片、默认联网搜索、长期对话记忆、自动执行 tool call、自动接受 Candidate 或绕过手工表单修改正式数据。
- 平台统一承担 AI 费用、任意自定义 AI endpoint/provider 和供应商管理后台；P3 采用用户自带 DeepSeek 凭据与固定官方 endpoint。

## 4. 信息架构与页面职责

## 5. 关键用户旅程与验收

### 5.1 首次建立计划

1. 用户创建学期，填写名称、起止日期和 IANA 时区。
2. 用户创建至少一门课程。
3. dashboard 从空引导切换为真实课程摘要。

验收：刷新和重新登录后仍处于同一学期；其他用户无法通过猜测 ID 读取该课程。

### 5.2 上传 syllabus 并录入

1. 用户在目标课程中上传 PDF。
2. 页面显示安全校验和已就绪资料，用户可以预览原文并打开既有手工表单；上传本身不创建 Import Run，也不改变正式计划。
3. `MANUAL_ONLY` 下用户对照原文填写日期、成绩组成或事项，明确提交后正式记录才出现在时间线和 dashboard。
4. 仅在 `AI_ENABLED` 且用户凭据可用时，页面才提供“开始 AI 解析”，创建 Import Run 并显示进度；worker 完成后展示 Candidate/Evidence。
5. AI 路径中用户逐项接受/修改/拒绝/标重复，确认后正式事项才出现。无凭据不创建卡住的 run，而是保留手工入口。

验收：上传/预览不改变 dashboard；手工提交仍走既有所有权、领域和版本校验。仅在 `AI_ENABLED` 时追加：审核前 dashboard 不出现候选日期；每个接受项能查看原始 Evidence；重复提交审核不会产生两份正式事项或重复更新。

### 5.3 处理含糊信息

示例资料写着 “Midterm: Week 6, location TBA” 或 “due midnight”。`MANUAL_ONLY` 时用户对照原文选择待定或补充明确信息；`AI_ENABLED` 时系统把无法唯一解释的日期标为待定/需审核。两种模式都不自行选择某一天或午夜的含义。

验收：用户可以补成具体时间或继续保留待定；Source 原文件保持可回看。AI 路径还必须保留相应 Evidence。

### 5.4 查看繁忙周和冲突

用户在 dashboard 看到未来若干周的强度和冲突卡片，点击某格能看到组成该强度的课程事项、估计来源及截止日期。

验收：热力图只用正式记录；准确时间重叠显示为硬冲突，符合聚集阈值的同日截止显示为软提醒，两者文案和样式不同。

### 5.5 导出日历

用户筛选学期/课程并下载 `.ics`。重新导出同一事项时 UID 不变，日历客户端可以更新而非复制事件。

验收：纯日期事项导出为 all-day；有明确起止时间的考试保留区间；待定事项不导出并在页面列出遗漏数量。

### 5.6 建立课表并查看下一节课

1. 用户为一门课程添加多个 Lecture/TUT/PRA 课节并填写地点。
2. 用户在学期中设置 Reading Week，预览该周不生成常规课节。
3. dashboard 与 calendar 从同一正式课表展开今日实例。
4. dashboard 根据当前时刻显示下一节课、剩余时间与地点；课程进行中或今天无后续课程时使用对应状态文案。

验收：同一课节不会因多个页面各自计算而产生不同日期/时区；Reading Week 不显示常规实例；显式保留或改期可覆盖例外；地点未知时显示 TBA 而非空白。

### 5.7 录入成绩结果

1. 用户先维护成绩组成与占比。
2. 出分后手工填写已得分和满分；系统派生百分比与加权贡献。
3. 页面同时显示已获总评百分点、已出分部分百分比和已覆盖权重。
4. 用户提供并确认 A/B/C/D/F 边界后，页面才显示对应字母等级；课程学分单独展示。

验收：未出分组成不按零分；修改结果可追踪并带版本冲突保护；无等级表时不猜字母等级；首版不输出 GPA、最终预测或“已获学分”。

### 5.8 `AI_ENABLED` 后配置并使用个人 AI

1. 用户点击右上角头像进入个人中心；未配置密钥时看到“AI 功能暂不可用，请先配置 DeepSeek API Key”。
2. 用户输入自己的 key。CourseFlow 服务端验证认证和 `deepseek-v4-pro` 可见性，加密保存后只返回状态与掩码提示。
3. 用户可让 AI 解释本周优先级、生成计划草稿或拆解一个正式事项；服务端只发送该用户当前请求需要的有界正式快照。
4. 若 AI 建议变更，页面把结果放入现有手工表单，用户核对并提交后才写入正式记录。
5. 用户撤销密钥后，新的 AI 抽取/助手请求立即停用；已有正式课程计划不受影响。

验收：浏览器和普通日志都拿不到明文 key；未配置/无效/余额不足/限流/供应商失败可区分；模型回答不能读取其他用户或未审核 Candidate；关闭草稿不产生写入，提交草稿仍经过现有 command 的所有权、版本与领域验证。

若最终决定为 `MANUAL_ONLY`，本旅程和对应入口不存在；验收改为确认没有 AI 文案、密钥字段、AI route/表/依赖，用户仍能从 Source 预览完成手工录入并看到 P1/P2 的派生结果。

## 6. 产品规则

- 用户选择目标课程后上传；仅 `AI_ENABLED` 时 AI 可以建议修正课程代码/名称，但不能把资料静默移动到另一课程。
- 正式数据允许手工创建，不依赖 AI 成功。
- 被归档课程默认从 dashboard 隐藏，但历史数据和导出仍可选择。
- 评分合计异常、日期落在学期之外、重复标题/日期都产生 warning；除违反结构约束外不武断阻断用户。
- 冲突是派生事实，不修改课程事项本身。
- 统计洞察必须显示口径、范围和数据质量；没有足够数据时返回空状态而非猜测。
- 课节是周期规则，日历中的某次上课是派生实例；Reading Week/取消/改期不能通过删除原规则来伪装。
- “短期/中长期”与任务标签是课程事项的视图和组织信息，不创建第二套任务真相。
- 当前成绩必须伴随“已覆盖权重”，未出分组成保持未知。
- AI 只能解释正式投影或产生草稿；日期、Reading Week、冲突、成绩和审核真相仍由 core 决定，模型输出不能成为第二套真相。
- Source Document 上传与 AI 解析解耦：所有模式都可保存为 ready；`AI_ENABLED` 但没有可用密钥时不能创建一个注定卡住的 Import Run。
- AI 是经 [去留门禁](../architecture/AI_ASSISTANT.md#3-deepseek-ai-去留门禁) 才能启用的条件性能力；最终未通过就执行 `MANUAL_ONLY`，不保留隐藏 AI 或更换供应商。

## 7. 待产品确认但不阻塞骨架的选项

这些选项用配置或清晰 seam 保留，开始对应功能前再与用户确认：

- 生产部署平台和 auth provider。
- DeepSeek API 专属数据保留、训练退出、DPA/数据驻留和服务等级条款；未确认前只发送完成请求所需的最小文本并保持可撤回 BYOK。
- 是否按 locale 自动建议周起始日；首版固定默认周一且允许用户修改。
- 热力图是否允许用户自定义强度阈值；MVP 使用架构定义的版本化固定 policy。
- 日历是否加入默认提醒、提醒提前多久。
- 后续统计页首批 Insight（例如最忙周、各课程负荷占比、截止分布）。
- Reading Week 是否允许多个区间、学校特有的 PRA 名称和课节例外编辑细节。
- 用户提供的 A/B/C/D/F 等级边界、标签颜色/数量上限、课程学分与未来 GPA 语义。
