# CourseFlow UI 线框图与页面说明

> 状态：书面 UI 规格已由用户批准
> 版本：1.8
> 日期：2026-08-28
> 方法：Superpowers brainstorming + visual companion
> 适用平台：macOS / Windows 本地优先桌面应用

## 1. 文档目标

本文把已经确认的 User Flow、PRD 与视觉线框整理为可同时服务 UI 细化、实现拆分和开发验收的页面规格。每个页面说明包含：

- 用户目标与进入条件。
- 页面区域及信息优先级。
- 主要操作与所用表面。
- 空状态、异常状态和恢复方式。
- 页面完成状态。
- 对应 User Flow 与 PRD 编号。

本文是信息架构、交互语义和页面状态的正式基线。后续视觉细化可以优化材质、间距、字体、色值和细节构图，但不得在未重新确认的情况下改变页面范围、数据语义、破坏性操作范围或 MVP 层级。任何外部生成式设计成果均不作为本文、后续实施或验收的依据。

## 2. 范围与发布边界

### 2.1 首发发布剖面

完整产品设计保留 24 个表面，其中 5 个 `UI-GRADE-*` 是 C1 未来设计；首发只验收其余 19 个表面。首发导航固定为 `Today`、`Courses`、`Calendar`、`Tasks`、`Files`；C1 实际交付后在 `Tasks` 与 `Files` 之间加入 `Grades`，未交付时不显示禁用或占位入口。

### 2.2 本文详细覆盖

- MVP-A：首次进入、可恢复设置、今天首页、课程与课表、任务、周日历与议程、备份恢复、迁移回退、学期历史。
- MVP-A 外围目标：默认关闭、从当天生效的可选课节出席记录。
- MVP-B：受管理的本地文件资料库。
- C1 未来设计：评分方案、成绩录入、单科总成绩、等级/绩点模板和当前学期估算 SGPA。

### 2.3 只保留结构连接点

- EXT-C2 目标成绩与所需分数：MVP 不显示禁用导航、空白目标页或“即将推出”卡片。未来可从单科成绩结果区和学期 SGPA 区接入。
- EXT-C3 Academic History：从大一开始的历史学年、补录缺失学期与累计 CGPA 已记录在 FUTURE_MEMO.md；MVP 不显示入口。
- 本周负荷与番茄钟：今天首页布局保留未来可重排容量，MVP 不显示占位卡、模拟数字或不可用操作。

### 2.4 明确不新增

- 不新增账户、远程后端、AI、OCR、LMS 或外部日历同步。
- 核心旅程保持离线可用，未经用户明确操作不得上传课程、成绩或文件内容。追溯：NFR-001。
- 不新增系统后台通知、邮件或短信。
- 不新增应用内更新检查、下载进度、自动安装、应用商店或发布频道页面；用户在应用外手动取得版本。
- 不把视觉参考图中的搜索、通知、人物、薪资等无关控件带入产品。
- 页面级搜索只在已定义模块内出现，例如文件资料库筛选；未定义的全局搜索不进入 MVP。
- 不为手机设计独立导航或页面。

## 4. 已确认的设计系统方向

### 4.1 信息架构

首发主导航从左到右固定为：

1. Today
2. Courses
3. Calendar
4. Tasks
5. Files

应用启动并存在可用数据时始终进入 Today。顶栏右上只保留首发真实存在的设置入口；设置不占主导航标签。C1 实际交付后完整顺序为 `Today`、`Courses`、`Calendar`、`Tasks`、`Grades`、`Files`。当前主导航必须同时显示图标或文字标签中的至少一种明确名称；不能只凭位置识别。

### 4.2 页面表面

| 表面 | 使用范围 | 行为 |
|---|---|---|
| 页面 | 浏览、列表、复杂结构和完整上下文 | 导航切换保留合理的筛选、滚动与选择状态。 |
| 右侧抽屉 | 快速创建、轻量编辑、录入一次成绩 | 标准桌面约 440–520px；紧凑桌面覆盖内容；内容区独立滚动、底部操作固定；Esc 关闭并恢复触发点焦点。 |
| 独立详情页 | 课程详情、重复规则、评分方案、文件预览等复杂内容 | 可直接返回来源列表并保留来源上下文。 |
| 模态框 | 首次设置、影响范围选择、恢复预览和破坏性确认 | 锁定焦点；背景不可操作；关键模态框不允许点击外部意外关闭。 |
| Toast | 完成、跳过等可逆短操作 | 不抢焦点；提供短暂撤销；屏幕阅读器可获知状态。 |

### 4.3 视觉材质

- 页面背景以中性白/浅灰为主，仅在局部右上或强调区域出现小范围白到暖黄渐变；不得让整页持续泛黄。
- 普通卡片使用无色半透明白色磨砂材质，颜色主要来自背景和课程强调色。
- 视觉原型建议范围为白色 48%–58% 透明填充、20–28px 背景模糊、浅色高光边框；具体值在实现阶段通过对比度与跨平台视觉验收确定。
- 深色仅用于选中的导航、小型主操作或必要焦点区域。日历事件、考试和普通内容卡不得成为大块纯黑区域。
- 卡片圆角应统一而克制；日历事件采用更小圆角和更高信息密度。
- 阴影用于区分表面层级，不能作为唯一边界。

### 4.4 颜色系统

- 每门课程可从红、橙、黄、绿、蓝、紫、灰等候选色中选择；精确色值暂定，后续可调整。
- 课节、任务、文件标签和成绩行可继承课程色，但必须同时显示课程代码或名称。
- 日历任务使用约 50% 透明课程色并配合轻微模糊/磨砂，课节可使用更实的浅色填充或左侧色条。
- Reading Week 等假期使用中性色，不与课程色竞争。
- 状态不可仅靠颜色：完成、跳过、逾期、TBA、缺席、未出分和错误都必须有文字或图标加文字。
- 状态色是与强调黄分离的独立词汇，各自成对提供前景色与底色：`critical`（逾期、失败）、`warning`（今天截止、待确认）、`success`（已完成）、`neutral`（TBA、已跳过、未来、已结束等其余状态）。
- 强调黄只表示选中态与当前态，永远不表示逾期或错误。课程色只作小面积强调，不参与状态语义。

### 4.5 桌面响应式

| 视口 | 布局 |
|---|---|
| 1920px 以上，含 2560×1600 | 顶栏铺满窗口；主内容扩展到约 1920px 后居中。增加并列面板和留白，不无限拉长正文。 |
| 1280–1919px | 标准桌面布局；1440×900 为主线框尺寸，1280×720 为最低标准验收尺寸。 |
| 1024–1279px | 紧凑桌面；抽屉变覆盖层，表格保留重点列并通过详情访问完整字段。 |
| 低于 1024px | 继续采用紧凑桌面与滚动，不生成手机导航；MVP 不承诺移动端体验。 |

多列页面网格的实装断点是 `≤1080px` 与 `≤820px`：四列或两列网格在 `≤1080px` 降为两列，在 `≤820px` 降为单列。上表描述意图，列数变化的判定以这两个实装值为准，不另设 1024px 断点。

日历在紧凑宽度仍保持七日语义；若每列无法保持最低可读宽度，时间网格允许横向滚动，日期分隔线和全天区域仍属于同一网格。

macOS 与 Windows 使用相同信息架构、状态语义和核心旅程；窗口装饰、文件选择器和系统打开行为可遵循各平台惯例，但不得造成平台功能缺失。追溯：A-PLATFORM-001。

## 7. 入口与首次设置

### 7.1 UI-ENTRY-01：首次欢迎

**用户目标**：在没有有效活动数据时，明确开始新本地数据或安全恢复既有快照。

**前置状态**：应用首次启动，或用户明确重置后不存在可用活动数据。

**线框**：

    ┌───────────────────────────────┐
    │ CourseFlow                    │
    │                               │
    │ 欢迎使用 CourseFlow           │
    │ 无需账户，数据默认保存在本机  │
    │                               │
    │ [＋ 开始新的本地数据       ›] │
    │ [↺ 从备份恢复             ›] │
    │                               │
    │ 不会静默扫描、上传或覆盖数据  │
    └───────────────────────────────┘

**交互**：

- “开始新的本地数据”创建空白活动数据并打开 UI-SETUP-01。
- “从备份恢复”进入 UI-DATA-02；恢复完成后根据数据完整度进入“今天”或 UI-SETUP-01。
- 页面不要求登录，不要求先选云盘，也不展示模拟课程。

**失败与恢复**：

- 创建活动目录失败时解释路径和权限，保留欢迎页。
- 找不到有效快照时显示真实空状态，并允许返回开始新数据。

**完成状态**：用户已明确选择新数据或经过验证的恢复流程。

**追溯**：UF-A-01；A-DATA-001、A-DATA-005、A-DATA-006；STATE-001、STATE-002；MVP-DOD-005、MVP-DOD-008。

### 7.2 UI-SETUP-01：可恢复设置清单

**用户目标**：以可中断方式建立最低可用学期，并可稍后补充非阻塞项。

**前置状态**：活动数据可写；首次设置尚未完成，或用户从设置中重新打开清单。

**布局**：

- 以约 1040×650 的大型模态框覆盖“今天”。
- 左栏为步骤与状态；右栏为当前步骤表单。
- 顶部显示“保存进度并退出”；底部显示状态说明与“进入今天”。只有一个必需步骤，因此不再有“上一步 / 下一步”。
- 点击模态框外部不关闭。Esc、关闭按钮或“进入今天”都先保存草稿状态。

**步骤**：

1. 当前学期：名称、开始日、结束日、学期默认时区。这是首次设置的唯一步骤。
2. 完成后模态框只显示“首次设置已完成”概览与四个非阻塞补充入口（课程、课节、任务、假期），每个入口直接打开对应的创建/编辑抽屉。

**补充管理表面**：

课程、课节、任务、假期与新建学期的创建表单由已批准的创建/编辑抽屉（§9.2、§9.4、§10.2）拥有，实现为一个带左侧分类导航的管理模态框，可从课程页、任务页和 UI-SETTINGS-01 打开。它是这些既有表面的交互形态，不新增页面、领域模块或数据接口，首发剖面仍为 19 个表面。

**最低完成条件**：

- 存在一个当前学期。

用户在未达到条件时仍可提前进入“今天”；缺失区域展示真实空状态与“继续设置”操作。达到条件后，清单状态改为“首次设置已完成”，其余课程、课节、任务、假期和备份仍可随时补充。

**假期分支**：

- 用户可直接跳过。
- 若某重复任务启用“跟随教学周”但当前学期尚无假期，显示“添加假期 / 明确暂不添加”，不阻止保存。

**保护数据分支**：

- 选择目录后验证可读写、与活动数据目录分离、与资料库根目录分离。
- 验证通过后立即创建首个快照。
- 跳过后显示“仅保存在本机”，不持续报错。

**失败与恢复**：

- 字段错误在字段旁说明并保留所有输入。
- 本地写入失败时不推进步骤，说明正式数据未改变。
- 备份验证或首个快照失败不撤销已完成的学期、课程或课节。

**完成状态**：最低条件满足，或用户明确提前进入首页且清单进度可继续恢复。

**追溯**：UF-A-02；A-TERM-001、A-TERM-004；A-COURSE-001–007；A-TASK-001–004；A-DATA-001–004；STATE-001、STATE-002。

## 8. UI-TODAY-01：今天首页

**用户目标**：打开应用后立即知道现在在做什么、今天有什么、下一步做什么，以及本周和学期处于什么状态。

> **MVP-A 实施说明（2026-09-01 重排，取代 2026-08-31 说明）：** 首发只交付 MVP-A 的 small/large 任务模型，
> 因此本页实现为「问候语 + 学期进度胶囊 + 三个行动数字」页眉，加一张四列三行、以今日时间轴为左侧日脊的网格，
> 共七张卡片：今日时间轴、现在、本周课时、下一步与本周截止（唯一深色面）、今日任务、课程、学期任务。
> 本节线框与槽位表描述的就是首发构建；2026-08-28 已批准的 Coursework/Assessment 分组在该模型实现前不出现。

**前置状态**：存在活动数据。无当前学期或学期已结束时进入对应真实状态。

**标准桌面线框（1420px 内容宽度，即 1920×1200 全屏下 `.workspace-page` 的 `max-width`；1280×800 为应用默认窗口）**：

    │                                            逾期任务  今日待完成  下一节 │

| 位置 | 槽位 | 类名 |

| 第 3 行 / 第 4 列 | 学期任务 | `.term-tasks-card` |

七个槽位都无条件存在；没有事实的槽位显示自己的空状态，网格不再有条件槽位或折叠逻辑。DOM 顺序与上表一致，即视觉阅读顺序（日脊、此刻、本周、下一步、今天、课程、学期），键盘与辅助技术顺序不需要额外处理。

**响应式**：`≤1080px` 降为两列：时间轴独占第 1 行，`现在 | 深色卡（跨第 2-3 行）`、`本周课时 | 深色卡`，其后今日任务、课程、学期任务各占整行；`≤820px` 单列按 DOM 顺序。沿用 §4.5 既有断点，不新增断点。

时间轴的可见时段与几何沿用 §11.1 为周日历设定的同一条规则：默认 07:00-22:00，真实课节或任务落在范围外时扩展到容纳它的整点边界，纵向偏移按整数优先的 `分钟 × 33 ÷ 60` 计算。一条时间规则同时服务日历和今日两个表面。时间轴卡片的高度由同一行的其他槽位决定，导轨在卡内独立纵向滚动并可键盘到达。60 分钟课节（33px）内标题行必须完整可见：事件条的标题行有保证的最小高度，短事件裁掉的是 meta 行的下缘，永远不是标题。

### 8.1 页眉

页眉直接落在画布上，不包卡片，**不设 eyebrow**（§17.2 为硬禁）。

- 左：问候语 H1（固定 rem 字号，不使用 `clamp()`）与一行 `日期 · TermZone · 第 n 周`。
- 右上：学期进度胶囊。
- 右下：三个大数字，`font-variant-numeric: tabular-nums`。

`第 n 周` 以 `plan.term.startDate` 所在周的周一为第 1 周起点，按 `plan.week.window.startDate` 落在第几周得出；这是两个 PLAN 日期之间的纯日期算术，不引入新的分类。`applicableDate` 早于 `plan.term.startDate` 时显示「学期未开始」，晚于 `plan.term.endDate` 时显示「学期已结束」，不显示第 0 周或负数周。

**学期进度胶囊**：

- 胶囊上方左右两端分别是学期名 `plan.term.name` 与「剩余 n 天」（`plan.termProgress.totalDays` 减 `plan.termProgress.elapsedDays`，两个 PLAN 数字之差）。
- 轨道代表 `plan.term.startDate` 至 `plan.term.endDate` 的完整日期轴，其宽度即 100%。轨道承载三种段：**已过**（轨道起点到 `plan.termProgress.ratio`）、**假期**（当前学期每条 HolidayRange 按其真实起止日期定位）、**剩余**（轨道未被覆盖的部分）。相邻段之间留 2px 画布缝。
- 段的位置只由日期映射到轴上得到，与日历事件按分钟定位属于同一类呈现几何。Renderer 不合并重叠假期、不去重、不统计假期天数。
- 假期段的事实来源是 `setup.holidayRanges` 中 `termId === plan.term.termId` 的条目。`plan.week.holidayRanges` 只覆盖当前一周，不足以填满一条学期长度的轨道，不得用作本段来源。
- `applicableDate` 早于 `plan.term.startDate` 时轨道保持平轨，右上角文字改为「n 天后开学」。

**三个大数字**：

| 位置 | 标题 | 值 | 事实来源 |
|---|---|---|---|
| 1 | 逾期任务 | 整数，为 0 时保留显示 | `plan.today.summary.excluded.priorOverdueTasks` |
| 2 | 今日待完成 | 整数，为 0 时保留显示 | `plan.today.summary.pending`，同时覆盖任务与应上课课节 |
| 3 | 下一节 | `HH:MM` 或降级值 | 见下方阶梯 |

逾期任务大于 0 时该格使用 critical 前景色，标题文字同时保留；状态不得只靠颜色表达（§4.4）。

**「下一节」降级阶梯**（取到哪级用哪级）：

1. `plan.today.meetings` 中第一个 `classification` 为 `in-progress` 或 `upcoming` 的课节，取其 `occurrence.localStart`；
2. 否则 `plan.week.meetings` 中第一个 `classification` 为 `upcoming` 的课节，取 `星期X HH:MM`；
3. 否则若 `plan.term.startDate` 晚于 `applicableDate`，标题降级为「学期开始」，值为 `plan.term.startDate`；
4. 否则显示「本周无」。

两个列表都已由 PLAN 按开始时间排序、分类也由 PLAN 给出，Renderer 只取第一个匹配项，不重新分类、不重新排序。页眉的第三格有意停留在本周尺度；跨周的「下一节」由「现在」卡和空状态阶梯（§8.3）承担。

### 8.2 槽位与事实绑定

**投影的覆盖范围**：`readPlanProjectionSource` 按整个 Term 展开课节与任务实例，因此 `plan.tasks`、`plan.meetings`、`plan.next.*`、`plan.tba`、`plan.termProgress`、`plan.courses` 是整学期事实；`plan.week.*`（含 `plan.week.days`）、`plan.calendar`、`plan.agenda`（含 `warnings`）绑定到 `evaluationContext.requestedWindow`，默认本周一至周日。`plan.meetings` 已由 PLAN 按开始时间排序并分类，其中第一个 `classification === 'upcoming'` 的条目就是学期内的下一节课；这是读取，不是推断。

| 槽位 | 内容 | 事实来源 | 空状态 |
|---|---|---|---|
| 今日时间轴 | 计时日程条、课程色块、冲突标记、当前时刻线 | `plan.calendar.timedItems` 中 `applicableDate` 当天的条目、`setup.courses[].color`、`plan.agenda.warnings`、`plan.evaluationContext.evaluatedAt` | 仍绘制导轨，说明块覆盖在导轨中央，文案按 §8.3 阶梯，两个动作（查看日历、添加课节） |
| 现在 | 当前时刻、一个环、状态标签、主值、一行 meta | 见下方状态表 | 空轨道，主值与 meta 按状态表 |
| 本周课时 | 七根柱（每天课时）、峰值 chip、今天高亮、柱下任务点、底部冲突 chip | `plan.week.days[]`、`plan.evaluationContext.applicableDate`、`plan.agenda.warnings` | 七个 3px 底座加一句话：开学前「学期 {startDate} 开始，本周还是空的。」，学期内「本周没有课节。」 |
| 下一步 + 本周截止 | 上半：大任务主块（大标题与倒计时）加小任务一行；下半：本周截止清单与 `n/N` | `plan.next.large`、`plan.next.small`、各自 `remainingMilliseconds`；`plan.week.tasks` 与其 `classification` | 上半两者皆空时单块单动作；下半为空时一句「本周没有截止的任务。」；不得出现两段逐字相同的文案 |
| 今日任务 | 任务列表、完成度 meter、severity chip | `plan.today.tasks`、`plan.today.summary.contributions.tasks`、`occurrence.displayProgress`、`classification` | 一句话，指向 TBA 任务数量 |
| 课程 | 当前学期课程 accordion：色点、代码、名称、教师、`{星期缩写} · n 节/周`；展开后教师/Section/学分与课节时段列表 | `setup.courses` 中 `termId === plan.term.termId && !archived` 的条目及其 `meetings[]`；标题右侧「本周 n 节」读 `plan.week.meetings.length` | 「还没有课程」加「添加课程」 |
| 学期任务 | 完成百分比、`已完成 a / b 项 · 按课程`、按课程分段的完成条、图例、逾期与 TBA chip | `plan.courses[]`（§8.4） | 「还没有任务」加一句说明与「添加任务」 |

**「现在」卡的状态表**（按顺序取第一个命中）：

| 状态 | 判定 | 环 | 主值 | meta |
|---|---|---|---|---|
| 上课中 | `plan.today.meetings` 中存在 `classification === 'in-progress'` | 已进行比例 `(evaluatedAt - startInstant) / (endInstant - startInstant)`，弧穿该课程的 `--course-accent` | 「剩 n 分钟」，`endInstant - evaluatedAt` 向上取整 | `{courseCode} {typeLabel} · 至 {localEnd} · {location}` |
| 课间 | `plan.today.meetings` 中仍有 `upcoming` | `plan.today.summary.contributions.meetings.completed / (completed + pending)`，弧穿 `--dark` | 到下一节 `startInstant` 的「n 小时 m 分后」（不足一小时只显示分钟） | `下一节 {courseCode} {typeLabel} · {localStart} · {location}` |
| 今天的课上完了 | 今天有课节但既无 `upcoming` 也无 `in-progress` | 同上（此时为满环） | 「今天 n 节课已结束」（n 为今天未取消课节数） | 学期内下一节：`下一节 {星期} {localStart} {courseCode}`（`plan.meetings` 第一条 `upcoming`）；没有则「本学期没有其他课节」 |
| 今天没有课 | 学期内、今天没有课节 | 空轨道 | 「今天没有课」 | 同上一行 |
| 开学前 | `applicableDate < plan.term.startDate` | 空轨道 | 「n 天」（到 `plan.term.startDate` 的日历日差） | `第一节 {星期} {localStart} {courseCode} · {MM-DD} · {location}`；没有课节则「还没有排课节」 |

在课比例与「当前时刻线」属于同一类时间几何，由 Renderer 从 PLAN 的 Instant 计算；其余数量全部来自 PLAN。环的轨道是 60 段刻度的表盘，弧以 `pathLength="100"` 定长；`prefers-reduced-motion` 下不过渡。环上没有播放或暂停控件。状态标签左侧的圆点：上课中为 `--morning-deep`，其余穿相关课程色，无课程时为中性灰。

**「本周课时」的读法**：柱高为 `plan.week.days[i].meetingMinutes` 相对本周最大值的比例；标题右侧「n 小时 · m 节」为七天 `meetingMinutes` 之和除以 60（保留一位小数，整数时不显示小数）与 `meetingCount` 之和；峰值 chip 只标最高的一天（并列时都标）；柱下最多 3 个圆点表示 `taskCount`，第 4 个圆点表示「3 以上」；今天的柱穿 `--morning-deep`，日标签同时变为黄底黄边胶囊，状态不只靠颜色。柱不超过 24px 宽，数据端 4px 圆角、基线为直角，不描边。`plan.agenda.warnings.length > 0` 时底部出现 warning chip「n 组时间冲突」加一行「{星期} {localStart} {first.courseCode} 与 {second.courseCode} 重叠」，只取第一组，其余由日历页承担。该数字覆盖的是整个 `plan.week.window`，标题必须写「本周」，不得写成「今日」。时间轴上的冲突标记同样只按 `agenda.warnings` 中出现过的 Meeting occurrence 身份打标，Renderer 不自行判定重叠。

**「本周截止」的读法**：`n` 为 `plan.week.tasks` 中 `classification === 'completed'` 的数量，`N` 为 `plan.week.tasks.length`（`skipped` 计入分母并划线显示，与 PLAN 的周列表一致）。行按 PLAN 已排好的截止顺序，最多 5 行，第 6 行起折叠为「还有 n 项在任务页。」。每行为勾选圈（`completed` 白底深色勾；`overdue` 圈边为深色面上的 critical 色；`today` 圈边为强调黄；其余为半透明白）、标题（完成态划线）、`{courseCode} · {星期} {HH:MM}` meta（date-only 只给星期，`overdue` 追加「· 逾期」）。行不可点击；任务操作留在「今日任务」与任务页，卡片只有一个「查看任务」动作。

**「今日任务」完成度的口径**：meter 使用 `plan.today.summary.contributions.tasks` 的 `completed` 与 `pending`，即只覆盖任务。页眉的「今日待完成」使用 `plan.today.summary.pending`，同时覆盖任务与课节。两处数字口径不同，标题必须分别说明，不得互相替代。`completed` 与 `pending` 之和为 0 时不渲染 meter，只保留文字。timed deadline 按 TermZone 显示为 `YYYY-MM-DD HH:mm`（`<time dateTime>` 保留精确 Instant），date-only 显示日期本身，TBA 显示「TBA」。

**「课程」的读法**：每行是原生 `<details>/<summary>`，键盘可达、无脚本状态；`summary` 去掉默认标记，`:focus-visible` 有可见轮廓，chevron 用 SVG 绘制并在展开时旋转。摘要行的 `{星期缩写}` 来自该课程 `meetings[].weekday` 去重排序，`n 节/周` 为 `meetings.length`。展开内容中的时段按 weekday、localStart 排序。行之间用 1px `var(--line)` 分隔，不把每门课包成卡。默认全部折叠。

**三项注意事实各归其位**：逾期任务数已在页眉（critical 色），逾期任务本就出现在「今日任务」列表与「本周截止」清单；本周时间冲突在「本周课时」卡底部；TBA 数量在「学期任务」卡底部，且「今日任务」空状态继续点名 TBA 数量。2026-08-31 版本的「需要注意」卡与页脚说明不再存在。

### 8.3 空状态降级阶梯

课节相关空状态（今日时间轴的说明块、「现在」卡的 meta）按以下阶梯取文案，取到哪级用哪级：

1. `plan.today.meetings` 中仍有 `classification === 'upcoming'` 的课节：「下一节 {localStart} {courseCode}」；
2. 否则 `plan.week.meetings` 中有 `upcoming`：「本周下一节是{星期} {localStart} 的 {courseCode}。」；
3. 否则 `plan.meetings` 中有 `upcoming`（跨周）：「下一节 {MM-DD} {星期} {localStart} {courseCode}。」；
4. 否则若 `plan.term.startDate` 晚于 `applicableDate`：「学期 {startDate} 开始，还没有排课节。」；
5. 否则：「本学期没有其他课节。」，并给一个通向日历页的动作。

第 3 级读取的是 PLAN 已排序分类的整学期列表的首个匹配项，不是 Renderer 的推断（§8.2 首段）。「本周课时」「本周截止」与「今日任务」的空状态只引用 `plan.week.*`、`plan.tba.tasks.length` 与 `plan.term` 里已有的事实。

空状态文案使用学生语言，说明缺少的真实对象和可执行的下一步；不解释投影不变量（例如「统一计划投影确认……取消或假期抑制不会伪装成课程」属于被替换的写法）。分级规则见 §17.8。

### 8.4 排序、选择与统计

- 今日时间轴按开始时间排序；进行中和即将开始有文字状态。
- 「下一步」的主块固定为大任务、次行固定为小任务，不按剩余时间在两者之间挑选。两者分别从未完成、未跳过且日期已知的对应任务组中由 PLAN 选出。
- TBA 任务不参与倒计时，进入「学期任务」卡的 TBA 计数与任务页。
- 任务状态使用 severity chip（§17.9）：逾期为 critical、今天截止为 warning、已完成为 success。黄色只作强调色，永远不表示逾期。
- 今日计数同时覆盖任务和应上课课节；假期抑制和取消课节不计。
- 出席关闭时，已结束课节按时间进入已完成统计，未来或进行中课节进入待完成。
- 出席开启时，Present 与 Late 计入完成并保持不同标签；已结束 Unmarked 进入待确认；Absent 单独显示；Excused 显示为已处理且不进入完成、缺席或待确认；未来/进行中仍待完成。
- 学期进度使用学期时区中的日历日和包含首尾两日的公式：（今天 减 学期开始日 加 1）除以（学期结束日 减 学期开始日 加 1），并限制在 0%-100%。Reading Week 不从分母扣除；不使用任务完成率替代日期进度。
- **每日负荷** `plan.week.days`：七条，从 `plan.week.window.startDate` 起连续；`meetingCount` 为当天 `plan.week.meetings` 中 `classification !== 'cancelled'` 的数量，`meetingMinutes` 为这些课节 `(endInstant - startInstant)` 的分钟和（跨日课节归入开始日、取全长），`taskCount` 为当天截止的 `plan.week.tasks` 数量（含 completed 与 skipped）。
- **学期任务完成度** `plan.courses`：每门在 `plan.tasks` 或 `plan.meetings` 中出现过的课程一条，按 `courseId` 稳定排序；`completed`、`pending`（overdue + today + near-due + future）、`overdue`、`tba`、`skipped` 与 `countable = completed + pending + tba`。**跳过的任务不计入 `countable`**：跳过表示不再要做，分母也不算它。页面百分比为 `Σ completed / Σ countable`，`countable` 为 0 时显示 `0%`。分段条中每门课一段，段宽 ∝ `countable`，段内实心宽 ∝ `completed / countable`，段底色为同色浅一阶。没有任何实例的课程由 `setup.courses` 补齐并以 `0/0` 显示。

**Renderer 边界**：本页不重新计算分类、选择或汇总。按稳定 ID 查 `setup.courses[].color`、按 PLAN 已给出的分类取列表首项、把 PLAN 事实放进日期列或时间轴位置、显示两个 PLAN 数字之差或之和、把 PLAN 的 Instant 换算成环上的比例，都属于呈现；新增一个投影里没有的判定、阈值或统计口径则不属于。每日负荷与按课程汇总因此由 PLAN 的 `buildPlanProjection` 产生，Shell 只读。

### 8.5 直接操作与真实状态

- 任务可直接「完成」或「跳过」。
- 操作本地持久化成功后显示 6 秒撤销 Toast；悬停或键盘聚焦时暂停计时。
- 编辑内容、重复规则和已开启进度时才进入详情或抽屉。
- 出席开启且课节已开始后可直接记录 Present、Absent、Late 或 Excused；允许恢复 Unmarked。

真实状态：

- 设置未完成：保留可用槽位，缺失槽位显示下一步与「继续设置」。
- 当日无课：时间轴仍绘制导轨并在导轨中央说明今天没有课节，不隐藏「下一步」；「现在」卡进入「今天没有课」或「开学前」状态。
- 无任务：「今日任务」显示一句话空状态并指向 TBA 数量；「本周截止」显示一句话；「学期任务」显示空状态。
- 没有课程：「课程」卡显示空状态并提供「添加课程」。
- 学期已结束：显示结束说明、100% 日期进度、「创建新学期」为主操作、「查看历史」为次操作。
- 数据局部失败：不受影响的槽位继续工作；失败槽位说明范围和重试方式。

**完成状态**：用户无需进入其他页面即可识别现在正在上或将要上什么课、今天课节的时刻分布、下一步任务与本周截止、本周每天的负荷与冲突、当前学期课程清单和按课程的任务完成度，并能完成/跳过任务。

**追溯**：UF-A-03；A-VIEW-001-006；A-TASK-002、A-TASK-003、A-TASK-008、A-TASK-009；A-ATTEND-003、A-ATTEND-005；STATE-001、STATE-002、STATE-006。

## 9. 课程与课表

### 9.1 UI-COURSE-01：课程列表

**用户目标**：浏览当前学期课程，并快速创建或进入某门课程。

**前置状态**：存在当前学期；否则显示创建/切换学期。

**结构**：

- 页头：当前学期、课程数量、添加课程。
- 主区：课程卡或紧凑列表，显示课程色、代码、名称、教学范围、LEC/TUT/PRA 数量、下一课节。
- 筛选：当前/已归档；MVP 不需要复杂全局搜索。

**主要操作**：

- 添加课程打开右侧抽屉。
- 选择课程进入 UI-COURSE-02。
- 归档课程必须预览对当前课表和待办的影响；默认从当前视图移除但保留历史。

**状态**：

- 无课程：解释最低设置条件并提供添加课程。

**页眉**（§17.2）：主标题「任务」、当前学期上下文，右侧一个直接落在画布上的容器同时放三个数字与一个主要操作「添加任务」，不包卡片。数字 `font-variant-numeric: tabular-nums`，字号与 Today 页眉的三个行动数字相同，是本页唯一的主数字尺寸。

| 位置 | 标题 | 事实来源 |
|---|---|---|
| 1 | 待完成 | Σ `plan.courses[].pending` 加 Σ `plan.courses[].tba`：未完成、未跳过的全部实例，含尚未定日期的 TBA；逾期计入其中 |

**主体网格**：`grid-template-columns: minmax(0, 1.35fr) minmax(18rem, 0.65fr)`，两列顶部对齐；右列是一个纵向堆叠两张卡的容器，卡片各按内容取高。`≤1080px` 单列，顺序为左列卡、按课程、TBA，沿用 §4.5 既有断点。

**左列「按截止时间」**：

- **分组只按 PLAN 已给出的 `classification` 放行**：`overdue` 进「逾期」、`today` 进「今天」、`near-due` 进「即将到期」、`future` 进「未来」，四组按此顺序，组名就是 §17.9 的分类短文字，不另起「7 天内」一类的第二个名字；`completed` 与 `skipped` 进入卡片底部一个默认折叠的 `<details>`（摘要行「已完成 n 项 · 已跳过 m 项」），内部各自成组；分类为 `TBA` 的实例只出现在右列 TBA 卡。组标题带当前显示的行数「n 项」；没有可见行的组不渲染，折叠区只要有已完成或已跳过的实例就保持渲染（筛空时显示一句说明），让浏览器保住它的展开状态。「逾期」组标题用 critical 前景色，「今天」组用 warning 前景色，状态由标题文字本身表达。每组是一个 `<h3>` 加以它命名的列表，不再嵌套 region。Renderer 不重新分类、不改阈值、不在行上重复状态徽标。
- **组内顺序**：用 PLAN 自己的截止比较器（`compareTasksByDeadline`：截止边界，再稳定身份），与 `plan.week.tasks` 的顺序规则一致，因为 `plan.tasks` 本身按身份排列；已完成与已跳过组按同一比较器倒序，最近的在前，截止为 TBA 的实例排在最后。这是呈现排序，不是选择。
- **行**：课程色点（`setup.courses[].color`，无颜色为中性灰）、标题（可换行，不省略）、一行 meta `{courseCode} · 大任务|小任务`（明确开启进度时另起一段「进度 n%」，一行最多一个间隔点）、截止、直接操作。行之间 1px `var(--line)`，不把每行包成卡。行保留 `data-item-id` 与 `tabindex="-1"`。
- **截止的写法**：所有事实可见，不放进 `title`。「今天」组只写时刻「HH:mm」（date-only 写「今天」）；其他组写「MM-DD 周x HH:mm」，与 `applicableDate` 不同年时写完整日期，date-only 省略时刻；任何非「今天」组里截止日等于 `applicableDate` 的实例（逾期组里今天早些时候已过点的，或折叠区里今天完成的）写「今天 HH:mm」。逾期组的行在截止下方再写「逾期 n 天」，n 为截止日到 `applicableDate` 的日历日差（两个 PLAN 日期之差，与「n 天后开学」同一类算术），n 为 0 时不写。`<time dateTime>` 保留精确 Instant 或日期。
- **操作后的焦点**：完成或跳过后行会离开可见列表（进入折叠区或被筛掉）。Shell 在派发前记下紧随其后的任务行，恢复焦点时依次取：被操作行仍可见时它的可用按钮或它本身；否则下一行的可用按钮或下一行；否则收纳它的折叠区 `<summary>`；否则页面标题。不把焦点交给关闭的 `<details>` 内部元素。
- **筛选**：卡片标题下一行 chip，独占一行，任何宽度下位置固定：「全部」「大任务」「小任务」，以及每门有任务实例的当前学期课程一个 chip（课程色点 + 代码，按 setup 顺序）。chip 组是一个 `role="radiogroup"`，只占一个 Tab 位，左右方向键与 Home/End 移动并选中，`aria-checked` 表达选中。选中态用强调黄底加 1px 深色描边与加粗（§4.4：黄色只表示选中与当前；深色描边与字重是不靠颜色的载体）。筛选是 **Renderer 视图状态**（`workspace-view-state.ts` 的 `TaskListFilter`）：由 Shell 持有、页面切换内保留（§4.2）、提交与重查不重置、不持久化、不新增 Query；被筛课程不再有任务实例时按渲染时解析回到「全部」，不写状态。筛选作用于本页所有任务行（四组、折叠区与 TBA 卡），但不改任何 PLAN 数字：页眉、按课程卡、TBA 卡标题的「n 项」都不变。卡片标题右侧一行 `role="status"` 常驻：未筛选写「共 n 项」，筛选时写「{chip 名} · 显示 k / n 项」（n 为四组行数之和，k 为可见行数）；TBA 卡筛选时标题右侧写「显示 k / n 项」。左列卡内所有计数都是当前显示的行数。筛选把四组都筛空时只显示一句「当前筛选下没有待完成任务。」和「清除筛选」，清除后焦点回到「全部」chip。
- **动效**：chip 的颜色过渡 120ms、按压 `scale(0.98)`；行与折叠区摘要的 hover 只在 `(hover: hover) and (pointer: fine)` 下变底色；折叠区用原生 `<details>` 切换，chevron 旋转 180ms；分组、行、chip、状态行都没有入场或交错动画；`prefers-reduced-motion` 下去掉过渡与按压位移。

**右列**：

- **按课程**：与 Today「学期任务」同一读法（§8.2、§8.4）：百分比 `Σ completed / Σ countable`、「已完成 a / b 项」、按课程分段条、两列图例、逾期与 TBA chip。图例不可点击；筛选选中某门课程时，该课程的分段与图例行加选中态（黄底加深色描边、图例加粗、分段条 `aria-label` 追加「已筛选 {code}」、图例行含视觉隐藏的「已筛选」）。`countable` 为 0 时只保留一句「还没有任务。」，不给动作（§17.8 次槽位）。
- **TBA**：只放 PLAN 分类为 `TBA` 的实例（待完成且截止未定），标题右侧「n 项」与按课程卡的 TBA chip 同口径；一句说明「还没定日期或时间，不算倒计时，也不会逾期。」，行与左列同形但没有截止一列。空时一句「每个任务都有日期了。」；筛选筛空时一句「当前筛选下没有 TBA 任务。」。
- 学期没有任何任务时右列不渲染，避免三处重复的「还没有任务」。

**直接操作**：

- 待完成任务可直接完成或跳过。
- 已完成/已跳过可恢复为待完成。
- 操作在本地持久化成功后才更新正式状态并出现撤销 Toast。
- 点击行进入 UI-TASK-02；添加/轻量编辑使用右侧抽屉。

**真实状态**（主槽位空状态按 §17.8 分级，取到哪级用哪级）：

1. 学期没有任务且 `setup.minimum.hasCurrentTermCourse` 为假：「还没有课程」，说明「先添加一门课程，任务会挂在它下面。」，唯一动作「添加课程」。
2. 学期没有任务：「当前学期还没有任务」，开学前说明「学期 {startDate} 开始，还没有任务。」，否则「给课程添加作业、测验或项目，它们会按截止时间排在这里。」，动作「添加任务」与「查看课程」。
3. 有任务但 `plan.next.small` 与 `plan.next.large` 都为空（没有截止已知的待完成任务）：「没有待完成的任务」，TBA 大于 0 时说明「还有 n 项没定时间的任务在 TBA 里。」并追加页内链接「查看 TBA 任务」，否则「本学期的任务都已完成或跳过。」，动作「添加任务」；折叠的已完成与已跳过仍渲染。
4. 筛选筛空：主槽位只显示一句话和「清除筛选」，这是视图状态而非投影空态；折叠区按筛选结果显示行，或一句「当前筛选下没有已完成或已跳过的任务。」。

- 只有 TBA：按截止时间的四组为空（第 3 级），TBA 卡可见。
- 逾期：保留原截止时间与逾期天数，写法见上。
- 重复实例：只显示该实例状态，不把整个规则标为完成。
- 计划投影不可用：页面级不可用状态（§18），说明范围与重试方式，不折叠。

**Renderer 边界**：按 PLAN 分类放组、用 PLAN 的比较器排序、求 PLAN 数字之和、按稳定 ID 查颜色、把 PLAN 日期换算成相对标签与日差，都属于呈现；新增判定、阈值或统计口径则不属于。

**完成状态**：用户能识别待办范围与每组的紧迫程度、按大小或课程收窄视图、执行状态改变，并在列表和首页看到一致结果。

**追溯**：UF-A-05；A-TASK-001–009；A-VIEW-003、A-VIEW-004；STATE-001、STATE-002、STATE-003。

### 10.2 任务创建/编辑抽屉

**字段**：

- 标题、可选 Notes 和课程；从课程详情进入时以 `<CourseName>` 为主要上下文，从全局入口进入时该位置是课程选择器。
- 两层类型：先选 Coursework/Assessment，再显示所属四个预设类型；每组另有低强调 `Other` 入口并要求自定义名称。
- 单次或每周重复。
- 纯日期、五分钟粒度的精确时间或 TBA。
- 重复时：星期、时间、开始日期、结束日期。
- “跟随教学周”开关。
- 与类型独立的可选 0–100% 自报进度；Project 与 Research Paper 直接展示，其他类型从更多选项开启。
- GRADE 可用时显示默认折叠的 `Counts toward grade`；可显式关联同课程既有评分项或创建新评分项。

**默认与校验**：

- 系统不从标题、文件、成绩分类或截止时间推断任务组与类型。
- Coursework 预设为 Homework、Assignment、Project、Research Paper；Assessment 预设为 Quiz、Term Test、Midterm、Final。Midterm/Final 保持 Term Test 子类型，通用 Term Test 仍可选择。
- 重复任务结束日建议使用课程教学结束日，必须由用户确认或缩短。
- TBA 不强迫输入虚构日期。
- 开启“跟随教学周”但尚无假期时，显示添加假期或明确暂不添加；不阻止保存。
- 进度不参与成绩计算；完成状态等价于显示 100%，但用户输入的进度本身不是正式成绩。
- 不提供手工 Reminder 字段；Today、本周、倒计时和临近截止从正式 Deadline 自动派生。
- `Counts toward grade` 只建议对应成绩分类，用户必须确认；任务分类以后变化不静默移动成绩项。
- Task 先在 PLAN 提交。随后 GRADE 关联失败时明确显示“任务已保存，成绩关联尚未保存”及重试，不把核心任务保存伪装为失败。

**日期选择器**：

- 日期字段按需打开紧凑月历，不在抽屉中永久占用整月高度；提供月份/年份、前后月和 Today。
- 支持方向键、Page Up/Down、Enter 与 Escape；选中态使用现有黄色强调并同时提供文字/可访问状态。
- Term、Course 与 Task 复用同一日期语义；时间按 TermZone 解释，系统时区不同时显示说明。

## 12. MVP-B 文件资料库

### 12.1 UI-FILE-01：文件资料库

**用户目标**：在一个受管理根目录中按课程、分类、标签和名称找到真实文件。

**前置状态**：系统 Documents 通过本地卷与已知云目录检查时可在其中创建默认资料库；Documents 被识别为云盘/远程位置时要求用户另选。对无法排除任意第三方同步的普通本地路径，界面必须解释检测限制并取得确认。文件模块失败不得阻止其他模块。

**布局**：

- 页头：根目录连接状态、“在文件管理器中打开”、“添加文件”。
- 根目录状态条：真实路径、本地性、根身份、可读写/watcher 状态、最后完整扫描时间和下一次兜底核对时间。
- 左侧筛选：所有文件、最近添加、待归类、课程、分类。
- 主区：名称搜索、课程/分类/标签/类型组合筛选、列表/网格切换。
- 文件列表：类型、文件名、真实相对路径、课程、分类、派生标签、自定义标签、状态。

**标签语义**：

- 学期、课程、分类来自目录位置，是只读派生标签。
- 自定义标签独立保存；在受管理目录内移动文件时不丢失。
- 位于根内但不属于已映射 Term/Course/Category 目录的普通文件显示“待归类”；不根据目录名自动建立课程或分类，用户可以把它移动到有效分类。
- 组合筛选结果只来自真实索引，不用示例或缓存虚构文件。

**目录与分类管理**：

- 系统按已有学期和课程建立目录映射，并提供考试、笔记、作业、练习、其他等建议分类。
- 新建或重命名课程后，只在真实文件系统操作成功时更新目录映射。
- 用户可增加、重命名或删除分类；操作前显示其中的文件数量和目标路径。
- 删除仍含文件的分类时，必须先选择移动到其他分类或取消，不能静默删除其中的文件。
- 分类或目录操作失败时保留原目录、原索引和用户操作上下文。

**外部变化**：

- 应用运行时发现手动放入、移动或删除；即使 watcher 提示完全丢失，根可访问且应用持续运行时也最迟每五分钟启动一次完整核对。
- 关闭期间变化在下次启动或重新扫描时发现。
- 状态条说明新增、移动、缺失、待归类、链接不受支持和等待身份确认的数量，并允许查看变化；系统无法可靠区分外部移动或同路径编辑/替换时，用户选择“同一文件 / 替换文件”，确认前不把旧身份、历史或自定义标签套到当前磁盘对象；索引更新仍以磁盘事实为准。

**空状态**：

- 显示资料库位置和三个下一步：添加文件、打开目录、重新扫描。
- 不把空资料库当成权限错误。

**追溯**：B-FILE-001–009、B-FILE-013；STATE-001、STATE-002；NFR-002、NFR-010。

### 12.3 UI-FILE-02：文件预览与详情

**用户目标**：确认文件内容、真实位置和标签，并执行受控文件操作。

**布局**：

- 主预览区：PDF、PNG、JPEG、WebP 或纯文本。
- 右侧属性：真实绝对路径、派生标签、自定义标签、可用状态。
- 操作：重命名/移动、“使用系统默认应用打开”、在文件夹中显示、删除。非高风险普通文件无论是否支持内置预览都显示系统打开操作。

**文件类型**：

- 支持内置预览的类型只包括 PDF、PNG、JPEG、WebP 和纯文本；扩展名与内容不一致时不尝试内嵌。
- PDF 提供页面滚动/跳转、缩放/适合页面、键盘控制、加载与失败状态公告，以及来源具备时的可选择文本层和结构信息。扫描件或缺少结构的文档明确说明限制；MVP 不提供全文搜索、活动链接、表单、脚本、批注、附件、打印或下载。

- 动画 WebP 只显示第一帧并标注“动画已暂停”；完整动画交给系统默认应用。

**磁盘一致性**：

- 重命名、移动和删除只有在磁盘成功后才更新正式索引。
- 删除明确说明“移入系统废纸篓/回收站”；平台回收能力失败时保留文件，不提供永久删除 fallback。
- 失败时保留原列表与详情，说明磁盘是否已改变。
- 预览期间检测到文件、根、权限或验证状态变化时立即停止继续读取并标为已失效；旧画面不得静默切换到新内容，用户必须显式重新加载。
- 系统打开只显示“已请求使用系统默认应用打开”或明确失败；不显示“已成功打开”。在文件夹中显示属于 best-effort 请求，不伪造成功回执。

**追溯**：B-FILE-006–010；STATE-002；NFR-001/002/006/010。

### 12.4 UI-FILE-03：冲突与异常

**同名冲突**：

- 同时展示现有文件与待添加文件的名称、大小和修改时间。
- 用户必须选择“保留两份 / 替换 / 取消”。

## 13. MVP-C1 成绩与当前学期 SGPA

### 13.1 UI-GRADE-01：当前学期成绩总览

**用户目标**：比较各课程当前或最终结果，并理解当前学期估算 SGPA 的覆盖范围。

**布局**：

- 摘要：当前学期估算 SGPA、已纳入学分、数据覆盖。
- 课程表：课程、百分比、字母等级、绩点、学分、结果来源、覆盖率。
- 未覆盖清单：缺少成绩、学分或有效模板的课程。
- 等级模板入口和设置课程成绩主操作。
- C1 实际交付后通过主导航 `Grades` 进入；课程详情的 Current grade 摘要进入对应单科页面。

**结果来源标签**：

- 当前估算。
- 手工最终成绩。
- 学校正式记录；MVP 仅允许用户明确录入并标记来源，不冒充自动同步。
- 信息不足。

**SGPA 公式**：

- 先将每门纳入课程的百分比映射为绑定模板中的离散绩点。
- 估算 SGPA = 各课程绩点 × 学分之和 ÷ 纳入课程学分之和。
- F 以 0.0 进入。
- 缺少成绩、学分或有效模板的课程进入未覆盖清单，不补零。
- 不先平均课程百分比再换算绩点。
- 页面不显示“学期总百分比”。

**状态**：

- 无课程成绩：提供逐课程设置入口。
- 仅部分课程可计算：显示估算 SGPA、纳入学分和未覆盖清单。
- 无任何课程可纳入：SGPA 显示“信息不足”，不显示 0.00。

**追溯**：C-GRADE-008–014；STATE-003、STATE-005；NFR-005、NFR-008。

### 13.2 UI-GRADE-02：单科成绩

**用户目标**：理解单科总成绩来自哪些评分项，并区分当前估算与最终结果。

**摘要指标**：

- 已出分部分百分比。
- 对应字母等级与绩点。
- 已获得加权百分点。
- 已覆盖总权重。
- 结果来源与绑定模板版本。

**评分项列表**：

- 顶层分别显示直接评分项和可折叠的分类组；分类组显示课程总权重、Equal average、已出分数/总数与当前分类平均。
- 每个评分项显示名称、可选关联任务和任务类型徽标；成绩分类名称由课程自定义，不与任务分类锁死。
- 已得分/满分或直接百分比。
- 直接项显示课程权重或“未知权重”；分类成员显示从分类总权重和项目数派生的有效权重。
- 加权贡献。
- 状态：已出分、未出分、缺少满分、未知权重。

**单科总成绩公式**：

- 单项百分比 = 已得分 ÷ 满分。
- 直接项有效权重等于自身课程权重；分类总权重为 `W` 且包含 `N` 项时，每项有效权重为 `W ÷ N`。
- 分类当前平均是已出分成员百分比的算术平均；未出分成员不按零处理。
- 已获得加权百分点 = 所有已出分且有效权重已知项目的单项百分比 × 有效权重之和。
- 已出分部分百分比 = 已获得加权百分点 ÷ 已出分且有效权重已知的总权重。
- 例如 33.8 加权百分点、覆盖 40%，当前估算为 84.5%。
- 84.5 保持 84.5，不自动向上取整成 85。
- 未出分、满分缺失或权重未知不按零分；明确录入的 0 分仍是有效成绩事实。
- 只有所有顶层权重已知且合计 100%、分类非空且所有必需评分项完成时，可显示“计算最终成绩”；用户也可选择“手工最终成绩”，但必须明确覆盖来源。

**权重警告**：

- 顶层直接项与分类组的已知权重合计不等于 100%，或仍有未知权重时，显示可解释警告。
- 系统不自动归一化、不擅自补足、不把未知设为 0。
- 新增或删除已有成绩分类中的成员会改变各成员有效权重，必须先显示对单科结果与 SGPA 的影响并明确确认。

**追溯**：C-GRADE-001–004、C-GRADE-008、C-GRADE-009、C-GRADE-012；STATE-003、STATE-005；NFR-005、NFR-008。

## 15. 数据保护、恢复与迁移回退

### 15.1 UI-DATA-01：数据与备份

**用户目标**：理解三个用户位置边界、确认本地保存状态，并分别管理快照、恢复保护与迁移安全副本。

**目录卡**：

| 位置 | 内容 | 规则 |
|---|---|---|
| 活动数据目录 | 数据库、设置、文件索引 | 本地正式结构化数据的唯一真相。 |
| 资料库根目录 | 课程文件 | 由文件模块监控，不得位于备份目录。 |
| 云盘备份目录 | 带版本与完整性信息的快照 | 只能用于备份，不运行活动数据库或资料库。 |

**备份状态**：

- 未配置：显示“仅保存在本机”，不报错。
- 等待中：本地保存已经成功，异步备份尚未完成。
- 成功：只在快照已于所选目录本地发布并重新验证后显示；展示最后成功时间、已保护修订、备份集、快照格式版本和完整性状态，同时注明这不代表云盘上传已经完成。
- 清理待完成：新快照仍是成功且可恢复；说明较旧快照尚未清理并提供重试，不回滚成功状态。
- 失败：说明原因和受影响范围，保留既有已验证快照与待备份状态，提供重试、释放空间或更换目录。

**恢复保护状态**：

- 恢复前安全恢复集与云盘 BackupSet 分开显示；它是一次整库恢复拥有的本地恢复点，不计入“最近两份已验证快照”。
- 恢复后首份常规快照尚未发布并验证时，显示“等待恢复后保护”；不得为了释放空间自动删除该安全恢复集。
- 首份常规快照验证成功后可以安全清理。未配置备份时继续显示独立本地恢复点，并只允许用户明确清理。
- 清理失败显示占用与可重试状态，不把已经成功的恢复降级为失败。

**迁移安全副本**：

- 与 BackupSet 和 RestoreSafetySet 分开显示；只保护最近一次前向 schema migration 以前的结构化数据，不包含真实资料库文件。
- 存在时显示已验证状态、源 schema、源修订、创建时间、尺寸和精确兼容 CourseFlow 版本/tag。
- “删除”先说明将失去该迁移的应用版本回退能力；没有自动清理、按时间过期或空间不足时静默删除。
- “回退”进入 `UI-DATA-03`，不直接替换数据。
- 副本损坏、缺失或没有仍可取得的精确签名目标版本时，不显示可执行回退；当前已迁移数据保持不变。

**快照列表**：

- 每项明确显示“已验证”“同步中或不完整”“损坏”“不兼容”或“未知条目”，并显示所属备份集；目录修改时间不决定顺序或可恢复性。
- 同一备份集自动保留并突出最近两份已验证快照；其他备份集、未知或无法验证的条目仍按真实状态展示，不计入自动保留，也不自动删除。
- 只有用户选择且当次重新验证通过的快照可以进入恢复向导。

**触发规则**：

- 正式数据本地保存成功后触发异步备份。
- 资料库变化完成真实索引后触发异步备份。
- 任一必需资料库文件缺失、未验证或复制期间变化时整份快照失败，不发布部分快照。
- 备份失败不回滚本地成功写入。

**追溯**：UF-A-07、UF-A-09；A-DATA-001–004、A-DATA-007；A-PLATFORM-002/003；B-FILE-012；STATE-002/007；NFR-002、NFR-003、NFR-012。

### 15.2 UI-DATA-02：快照恢复向导

**用户目标**：在不静默覆盖的前提下，从可信快照恢复。

**进入位置**：首次欢迎或“数据与备份”。

**步骤**：

1. 选择快照：按备份集和快照序号显示时间、学期、课程数、文件数、格式版本与候选状态；不根据目录时间自动选择最新副本。
2. 验证完整性：重新检查清单、格式、数据库、全部资料库文件、根身份和标签映射；同步中或不完整、损坏、不兼容及未知条目不能继续。
3. 选择资料库目标：当前根健康且其父目录可安全切换时保持原用户可见路径；没有当前根、当前根不可用或不能安全原位切换时，要求选择并验证一个新建或空本地目录。候选不含资料库时明确显示“恢复后无资料库根”。
4. 容量预检：按受影响卷显示活动数据、安全恢复集、候选暂存与回滚副本的峰值需求；不足时停止，并提供释放空间、重选资料库目标或取消。
5. 预览影响：当前数据健康时比较课程、任务、文件和设置，显示资料库目标、当前修订、根代次和恢复保护方式；当前数据损坏/只读而无法读取某个范围时明确显示“无法比较”，不填模拟差异。健康事实或受限恢复的原始证据发生变化都使本次预览失效。
6. 明确确认：说明这是一项完整替换且不自动合并。确认后立即进入维护状态；普通编辑、文件操作、备份与新恢复预览暂停，激活检查点前仍可取消。
7. 保护与激活：当前 DATA 与已配置资料库健康时创建本恢复会话独有的安全恢复集，再把候选暂存到最终目标所在卷并完整验证。当前 DATA 损坏/只读或已配置资料库无法完整读取时，只有旧原始证据能够保持不变且恢复控制位置可写，才显示带额外警告的“受限恢复”确认。界面以阶段和可取消性展示进度，不暴露真实路径或物理交换细节。
8. 重新打开：激活后验证结构化数据、全量对账资料库并恢复首次设置/当前学期路由；全部完成后才显示成功。

**禁止行为**：

- 不自动合并两个副本。
- 不在验证失败后继续。
- 不静默覆盖当前数据。
- 不把部分恢复显示为成功。
- 不用删除安全恢复集、既有已验证快照或跨卷复制删除来绕过容量/切换限制。
- 不把“可恢复的逻辑全有或全无”描述成一个跨结构化数据与资料库的操作系统原子事务。

**损坏快照**：

- 停止在验证步骤。
- 指出损坏类别。
- 允许返回选择其他快照。
- 原活动数据保持可打开。

**恢复失败**：

- 激活检查点前失败或取消时回到原活动数据，明确正式数据未改变，并保留可安全复用的候选选择。
- 激活检查点后中断时进入专用恢复页，普通工作区不可打开；页面内联显示当前可证明状态，只提供证据允许的“继续恢复”或“回滚”。若两者都不安全，则不显示物理动作并保持 recovery。
- 重启只可自动检查和补记由磁盘证据唯一证明的观察/完成记录；任何仍会改变数据或资料库的动作等待用户明确选择。
- 回滚也必须重新打开旧结构化数据、对账旧资料库并恢复路由后才显示完成。证据冲突、恢复协调记录损坏或结果不唯一时保持 recovery，显示当前状态详情且不猜测。
- 恢复已经成功但临时清理失败时显示“清理待完成”，不提供绕过完整恢复的一键回到旧数据；回到旧数据必须重新选择其安全恢复集并走完整向导。

**完成状态**：验证通过、影响已预览、用户明确确认，且新结构化数据重新打开、资料库全量对账和启动路由全部完成；检查点前未完成时原数据仍是正式数据，检查点后未收敛时只显示恢复状态，不宣称任一方成功。

**追溯**：UF-A-01、UF-A-07；A-DATA-005、A-DATA-006；STATE-002；NFR-002、NFR-003、NFR-010。

### 15.3 UI-DATA-03：迁移回退与等待指定版本

**用户目标**：理解回到迁移前数据的损失范围，使用精确兼容 CourseFlow 版本完成或取消回退，而不打开不一致的普通工作区。

**进入位置**：

- `UI-DATA-01` 的迁移安全副本卡片；
- 启动时检测到未终结 MigrationRollbackSession；
- source/target/错误 build 启动后的专用路由。

**影响预览**：

- 显示 safety copy 的源 schema/修订/创建时间和当前迁移后 revision/schema。
- 明确写出“迁移后新增或修改的结构化数据不会保留，也不会自动合并”。
- 说明真实资料库文件保持原位；目标版本会重新扫描并按磁盘事实对账，不能保证迁移后新增的结构化标签/映射继续存在。
- 显示唯一允许的 target version、tag 和当前平台 artifact filename；不提供任意旧版本选择器。
- 预览绑定当前副本、数据 revision、资料库 generation、source/target build 和影响摘要；任一变化要求重新预览。

**确认与准备**：

1. 破坏性确认模态框锁定焦点，默认焦点不放在确认按钮；必须明确确认数据损失。
2. 确认后进入 maintenance，普通编辑、文件操作、备份和其他恢复入口不可用。
3. 页面以“准备中 / 可以取消”“已到切换检查点 / 等待应用版本”等文字显示阶段，不暴露真实路径、DataSlot、journal sequence 或物理 rename。
4. 准备完成后说明应用将退出，并给出平台步骤：Windows 卸载当前 MSI 后安装指定 MSI；macOS 替换 `/Applications` 中的应用。

**按当前 build 呈现动作**：

| build | 页面与动作 |
|---|---|
| exact target | 显示“准备完成回退”，提供明确“继续回退”；完成前不打开普通工作区。 |
| exact source/current | 显示“等待目标版本”，提供等待说明；证据允许时可“取消回退并恢复当前数据”。 |
| 其他 build | 显示所需 target/source 版本；不提供继续、自动迁移或猜测性恢复按钮。 |

所有版本/文件名文本可选择复制，但不建立诊断导出或应用内下载。CourseFlow 不宣称外部安装器已成功；只在下一次启动通过 exact `appBuildId` 判定。

**中断与恢复**：

- 检查点前取消：当前迁移后数据保持活动，退出 maintenance。
- 检查点后 source build 取消：只有保留的当前数据重新激活、结构化数据打开、资料库全量对账并恢复路由后才显示取消完成。
- target build 继续：只有迁移前数据重新打开、资料库全量对账并恢复路由后才显示回退成功。
- handoff/slot/build 证据冲突或未知版本：保持 recovery，使用文字展示当前可证明状态；没有安全动作时 allowed actions 为空。
- 成功后不显示重复 safety copy；迁移前副本已经成为活动数据。

**无障碍**：

- 阶段变化通过 polite/必要时 assertive 状态公告；不逐条朗读内部操作。
- 全部动作可键盘完成；重新启动后焦点进入页面标题或当前问题摘要。
- “继续回退”“取消回退”等实际允许动作名称明确，不使用只有颜色/图标差异的按钮，也不虚构没有契约对应的退出动作。

**追溯**：UF-A-09；A-DATA-007；A-PLATFORM-002–004；STATE-002/007；NFR-002/003/006/007/012；MVP-DOD-009。

## 17. 全局组件规格

### 17.1 顶栏

- 左：CourseFlow 标识。
- 中：首发五个主导航为 Today、Courses、Calendar、Tasks、Files；C1 交付后为 Today、Courses、Calendar、Tasks、Grades、Files。
- 右：首发真实存在的设置入口。只在模块内部出现已经定义的搜索。
- 当前页面同时用填充、文字或可访问状态标识。
- 窗口缩小时可缩短间距或进入更多菜单，但当前页面和所有主导航仍可通过键盘访问。

### 17.2 页面标题区

- 主标题。
- 当前学期或页面上下文。
- 右侧最多一个主要操作、一组直接落在画布上的页面级事实，或两者同在一个右侧容器内。
- 次要操作使用普通按钮或更多菜单。
- 标题区不堆叠统计**卡**。页面级事实可以排在标题区右侧，但必须直接落在画布上，不包卡片、不加边框或阴影，并且只放该页最高优先级的少数几项；其余统计仍进入下方内容。Today 页眉的学期进度胶囊与三个行动数字按此规则实现（§8.1）。
- 标题区不使用 kicker/eyebrow 标签。标题自己承载页面身份，页面名已由顶栏导航的当前项表达；这是硬禁，不是偏好。

### 17.3 磨砂卡片

- 卡片是信息分组，不是所有内容的默认容器。
- 普通卡片无色半透明白；课程色只作为小面积强调。
- 背景模糊不可降低文字和控件对比度。
- 系统减少透明度/提高对比度时使用不透明浅色替代。

### 17.4 列表和表格

- 行选择、状态、排序不能只靠背景色。
- 紧凑宽度优先保留名称、状态和主数值；其他字段通过详情访问。
- 列表操作使用明确按钮或更多菜单，不依赖 hover 才可发现。
- 表格空状态占据内容区并提供下一步。

### 17.5 右侧抽屉

- 用于创建课程/课节/任务、轻量编辑和成绩录入。
- 标题、关闭、表单、固定底部操作。
- 关闭时如果有未保存更改，提示放弃或继续编辑。
- 保存中禁用重复提交；只有正式持久化后关闭。

### 17.6 模态框

- 用于首次设置、重复实例范围、出席启用、恢复预览和破坏性确认。
- 初始焦点落在标题后的首个合理控件或安全操作。
- 焦点循环在模态框内；背景不可操作。
- Esc 的行为明确；破坏性确认和首次设置不允许外部点击关闭。
- 关闭后焦点返回触发控件。

### 17.7 Toast 与撤销

- 完成/跳过等可逆状态默认显示 6 秒。
- 悬停、键盘焦点或辅助技术交互时暂停。
- 不抢焦点；通过状态区域宣布。
- Toast 消失后仍可从详情更正状态。
- 删除规则、替换文件、恢复快照等高影响操作不依赖 Toast 作为唯一保护。

### 17.8 空状态

空状态按槽位分级，不是每个空槽位都得到同一块完整空状态：

- **主槽位**（页面的锚，例如 Today 的今日时间轴与今日任务）：保留结构，给一句话说明和一个可执行的下一步。
- **次槽位**（例如 Today 深色卡里的「本周截止」清单、「本周课时」的冲突 chip）：只保留一句话或直接不渲染该片段，不给动作；卡片本身仍在网格里，因为它同时承载其他事实。空卡片本身也是噪声，所以 Today 的七个槽位各自都有不为空的主内容或明确的下一步。
- **页面级不可用**（投影读取失败）：说明范围与重试方式，不折叠。

每个显示出来的空状态必须包含：

1. 缺少的真实对象。
2. 用户可执行的下一步。

文案使用产品自己的学生语言，说明「现在没有什么」和「接下来能做什么」；不向用户解释投影不变量、模块边界或抑制规则。文案只能引用当前投影窗口内确实存在的事实；不足以说出更具体的事实时就说较粗的那一句，不得为了句子完整而编造（Today 的降级阶梯见 §8.3）。

空状态不显示 fixture、模拟数字、假按钮或“即将推出”。已结束、尚未开始、TBA、权限错误和真正为空是不同状态。

### 17.9 状态徽标

徽标同时携带短文字和 §4.4 的 severity：`critical`（逾期）、`warning`（今天截止、待确认）、`success`（已完成）、`neutral`（其余状态）。severity 只改变配色，不替代文字；去掉颜色后徽标仍然可读。

所有关键状态均使用短文字：

- 待完成、已完成、已跳过、逾期。
- 当前、未来、进行中、已结束。
- TBA。
- 当前估算、计算最终、手工最终、学校正式记录、信息不足。
- 本地已保存、备份等待中、备份失败。
- Unmarked、Present、Absent、Late、Excused、已取消、假期抑制。

### 17.10 日期与时间选择

- 日期字段按需打开紧凑月历，显示月份/年份、前后月和 Today；不在长表单中永久展开整月。
- 月历支持方向键、Page Up/Down、Enter、Escape，焦点和选中状态不能只靠颜色。
- 时间选择使用小时/分钟双列滚轮并支持直接输入；分钟严格按五分钟递增。
- 修改开始时间不自动顺延结束时间；Same day/Next day 必须由用户明确选择。
- 12/24 小时只按系统偏好格式化，正式时间仍按 TermZone 与明确的本地时间/Instant 语义保存。

## 18. 全局状态与失败恢复矩阵

| 状态 | 含义 | 界面要求 | 恢复 |
|---|---|---|---|
| 本地保存中 | 正式写入尚未确认 | 不显示成功；防止重复提交 | 成功后更新，失败保留输入 |
| 本地已保存 | 正式数据持久化成功 | 可立即返回页面 | 之后独立触发备份 |
| 备份等待中 | 本地成功、异步快照未完成 | 不阻塞用户 | 后台完成或显示失败 |
| 备份成功 | 完整快照已在所选目录本地发布并验证 | 显示备份集、已保护修订和“云端上传状态未知” | 等待外部云盘同步或继续使用 |
| 备份清理待完成 | 新快照已成功，旧快照清理未完成 | 不降级新快照；说明占用与原因 | 重试清理 |
| 备份失败 | 当前正式数据仍安全 | 显示既有已验证快照、待备份范围和原因 | 重试、释放空间或更换目录 |
| TBA | 日期或时间未知 | 进入待确定区域 | 用户补充日期/时间 |
| 未出分 | 尚无结果 | 不按零分 | 录入成绩 |
| 0 分 | 明确结果 | 显示 0 和来源 | 用户更正 |
| 未知权重 | 权重未确定 | 不进入加权范围 | 补充权重 |
| Unmarked Attendance | 有效期内尚未自报 | 不按 Absent | 记录 Present、Absent、Late、Excused 或保持未知 |
| 假期抑制 | 周期实例不应生成 | 不进入待办/出席分母 | 编辑假期或规则 |
| 文件未验证 | 根目录暂不可读 | 禁止宣称可用 | 重新授权/扫描 |
| 快照同步中或不完整 | 成员尚未全部可见 | 停止恢复，不等同于损坏 | 等待后重新验证或选择其他快照 |
| 快照损坏或不兼容 | 不能安全恢复 | 停止恢复并区分原因 | 选择其他快照或兼容版本 |
| 恢复维护中 | 已确认恢复，普通工作区暂停 | 显示阶段、后台进度和检查点前取消能力 | 等待、检查点前取消或处理明确问题 |
| 恢复待处理 | 激活检查点后尚未收敛 | 禁止打开可能混合的新旧工作区；用文字列出可证明状态 | 只在证据允许时继续或回滚；否则保持当前状态 |
| 恢复清理待完成 | 新工作区已成功，临时副本未安全清理 | 正常使用新数据；显示额外占用与原因 | 重试安全清理 |
| 迁移安全副本可用 | 最近一次前向迁移以前的结构化数据已验证 | 与备份/恢复安全集分开显示源版本、尺寸和回退目标 | 明确删除或进入影响预览 |
| 迁移待恢复 | 前向迁移未完成或尚未完整重开 | 普通工作区关闭；显示最后可证明 schema 状态 | 当前 build/证据允许时继续，否则保持 recovery |
| 回退等待目标版本 | DATA 切换已准备，尚未运行 exact target build | 显示精确版本/tag/制品名和手工替换步骤 | 安装目标版本；source build 可在证据允许时取消 |
| 回退错误 build | 当前程序既不是目标也不是原 source build | 不打开、不自动迁移；用文字说明所需版本 | 用户在应用外安装精确 target/source；无安全动作时保持 |
| 回退待完成 | exact target 已启动但 DATA/Library/路由尚未全部验证 | 保持专用页面并公告阶段 | 用户明确继续；失败按证据保持 recovery |
| 学期结束 | 日期超过结束日 | 首页显示真实结束状态 | 查看历史/创建新学期 |

## 19. 无障碍与输入方式

### 19.1 标准

以 WCAG 2.2 AA 为最低验收基线：

- 正文和图片文字对比至少 4.5:1；大字至少 3:1。
- 自定义指针目标至少 24×24 CSS px，或满足标准的间距例外；CourseFlow 主操作优先 32–40px。
- 键盘焦点不得被顶栏、抽屉、Toast 或磨砂覆盖层完全遮挡。
- 所有核心功能可使用键盘完成。

标准参考：

- https://www.w3.org/TR/WCAG22/
- https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum
- https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum

### 19.2 键盘

- Tab / Shift+Tab：按语义和视觉顺序移动。
- Enter / Space：按钮、复选框、切换、列表选择。
- Esc：关闭顶层抽屉/菜单/可关闭模态框并恢复焦点。
- 方向键：导航标签、分段控件、菜单和日期选择器。
- 日历拖拽不得是唯一方式；必须提供键盘可用的创建和编辑表单。

### 19.3 焦点

- 在浅色玻璃、暖黄渐变和深色按钮上都使用可见双层焦点环。
- 打开抽屉/模态框后焦点进入新表面；关闭后返回触发点。
- 校验失败后把焦点移动到错误摘要或第一个错误字段，并保留用户输入。

### 19.4 屏幕阅读器与状态

- 图标按钮有可访问名称。
- 课程色附课程代码/名称。
- 保存、失败、撤销、完整性验证等使用适当状态消息。
- 倒计时不逐秒朗读，只在有意义的阈值或用户主动查询时更新。
- 数据表具有列头关系；紧凑布局变为列表后仍保留字段名称。

### 19.5 动态与透明

- 跟随系统减少动态设置，关闭位移、缩放、视差和非必要弹性。
- 可保留必要的即时状态切换或轻微淡入，但功能不依赖动画。
- 参考 W3C 技术：https://www.w3.org/WAI/WCAG22/Techniques/css/C39
- 跟随系统减少透明度/高对比设置；磨砂失效时使用不透明表面保持层级。

## 20. 开发与视觉验收清单

### 20.1 页面完整性

- 首发五个主导航存在且顺序一致；C1 构建只在成绩能力真实可用时加入 Grades。
- 应用启动有数据时进入“今天”。
- 每个页面有真实空状态。
- 所有详细页面都能返回来源上下文。
- 未规划模块不显示禁用入口。

### 20.2 核心 A

- 设置可关闭、可恢复，最低完成条件准确。
- 首页同时显示今日课节/任务、下一个 Coursework、下一个 Assessment 和本周摘要。
- 完成/跳过只有持久化成功后更新，并有撤销。
- 课程支持一次原子创建零至多条 LEC/TUT/PRA；每条恰好一个星期、五分钟粒度时间、可选地点和课程内日期范围。
- 修改开始时间不自动顺延结束时间，跨日必须明确选择。
- 任务使用两层渐进分类和独立可选进度；八个预设类型不同时平铺为导航标签。
- 实例只提供“仅本次 / 本次及未来”；整条规则删除只在规则详情。
- Reading Week 是连续全天长条；日期竖线不中断。
- TBA 不落入虚构时间。
- 本地成功和备份结果独立。
- 备份成功仅表示所选目录本地发布并验证；同一备份集保留最近两份已验证快照，部分同步和损坏状态不混同。
- 恢复经过选择、验证、预览和确认。
- 手动更新没有应用内下载入口；需要 migration 时先建立一份已验证安全副本，错误 build 不打开普通工作区。
- 回退明确显示结构化数据损失、精确目标版本和资料库文件保留语义；只有数据重开、全量对账和路由完成后成功。
- 学期结束显示创建新学期，不自动复制旧课程。

### 20.3 可选出席

- 默认关闭。
- 首次或跨日启用从学期时区当天 00:00 开始；同日关闭后重开从实际重开时刻开始。
- 关闭在提交时刻立即生效；更早日期和关闭间隙不回溯。
- Unmarked 不按 Absent；Present、Absent、Late、Excused 保持不同状态。
- 关闭保留关闭前已有资格和记录。
- Late 计入出席率分子，Excused 排除于出席率分母；四种已记录状态进入 Coverage 分子，分母为零保持未知。
- 模块故障不阻塞核心 A。

### 20.4 文件

- 索引与真实磁盘一致。
- 默认根只在 Documents 通过本地卷/已知云目录检查时创建；任意第三方同步检测限制必须可见，任一时刻只有一个活动根。
- 应用上传复制文件。
- 外部新增/移动/删除可被发现；watcher 丢事件时最迟每五分钟启动完整核对。
- 布局外普通文件显示待归类；外部移动或同路径编辑/替换无法区分时等待用户确认。
- 派生标签和自定义标签分层。
- 同名文件不静默覆盖。
- 删除失败不永久删除；替换不继承被替换文件的自定义标签。
- 平台可识别的 symlink/junction、解析后越界路径和非普通文件/目录不被跟随，并显示明确问题；平台无法分类的特殊条目或范围显示为未验证，不宣称已识别操作系统的每一种特殊文件元数据。
- 根身份重新授权和当前路径 marker 修复不会采用任意已有目录。
- 磁盘失败不显示虚假成功。
- 权限丢失时其他模块仍可用。

### 20.5 成绩

- 0 分、未出分和未知权重分别显示。
- 顶层直接项与等权分类组可以并存；不支持嵌套、分类内自定义比例或 drop-lowest。
- 顶层权重总计异常只警告，不自动修正。
- 单科同时显示加权百分点、已出分部分百分比、覆盖权重，以及分类已出分数/总数。
- 分类成员有效权重由分类总权重除以成员数；改变已有成绩分类成员数前显示影响预览。
- 84.5 不自动进位为 85。
- 当前估算、计算最终、手工最终和学校正式记录来源不同。
- SGPA 先映射离散绩点再按学分加权。
- 缺少学分/成绩/模板进入未覆盖清单。
- 不显示学期总百分比、AGPA、CGPA 或 Academic History。

### 20.6 响应式与无障碍

- 在 2560×1600、1920×1080、1440×900、1280×720、1024×640 进行视觉 QA。
- 宽屏主内容约 1920px 后居中。
- 1024px 紧凑布局不丢失功能和字段访问。
- 键盘可完成所有核心旅程。
- 焦点可见且不被覆盖。
- 正文/大字对比满足 4.5:1 / 3:1。
- 主操作目标优先 32–40px，任何自定义目标满足 WCAG 2.2 最小目标要求。
- 课程颜色有文字替代。
- 减少动态和不透明替代模式下功能完整。

## 21. 视觉细化边界

书面 UI 规格确认后，可在用户提供的视觉参考基础上继续优化：

- 精确字体、字号比例和字重。
- 背景中性灰、白与局部暖黄的渐变范围。
- 无色磨砂卡片的透明度、模糊、边框与阴影。
- Bento 卡片比例和 2560×1600 宽屏构图。
- 课程候选色的最终色值及浅色事件填充。
- 日历事件密度、圆角、文字截断和重叠策略的视觉细节。
- 抽屉、模态框、Toast 和焦点环的动效细节。

视觉细化不得：

- 增加无 PRD 支持的功能、模拟统计或死入口。
- 把普通卡片或考试改成大块纯黑。
- 扩大黄色背景到主内容大部分。
- 仅用颜色表达状态。
- 改变备份、恢复、重复规则、成绩或出席的正式语义。
